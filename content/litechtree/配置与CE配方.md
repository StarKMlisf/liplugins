# 配置与 CE 配方权限

## 研究条件与奖励

先持有工作台研究「基础工艺」，免费获得 80 点；「整装出发」再提供 80 点。其他默认节点首次奖励覆盖本次费用，从 0 点即可依次研究全部 97 节点，无需管理员持续发点。农牧和建筑可穿插进行，工业与下界可并行，最终多条路线汇合为「世界工匠」。

每个节点可独立配置：

| 字段 | 作用 | 范围或格式 |
| --- | --- | --- |
| `parents` | 必须全部解锁的前置节点 | 节点 ID 列表，支持跨章，禁止循环 |
| `cost` | 本次消耗的研究点 | 整数 0~1000000000 |
| `reward-points` | 首次正常研究奖励的研究点 | 整数 0~1000000000 |
| `requirements.items` | 原版物品持有条件 | Bukkit 材质到数量的映射，数量 1~2304 |
| `requirements.ce-items` | CE 自定义物品持有条件 | `namespace:item_id` 到数量的映射，数量 1~2304 |
| `requirements.levels` | 最低原版经验等级 | 整数 0~1000000，0 为不限 |
| `requirements.permissions` | 研究前必须全部具备的准入权限 | 小写权限列表，禁止通配符；空列表为不限 |
| `requirements.advancements` | 必须完成的原版进度 | `namespace:path` 列表，空列表为不限 |
| 节点外层 `permissions` | 研究后授予的配方权限 | 小写权限列表，禁止管理权限和通配符 |

材料检查包含**主背包、装备和副手**，不消耗任何物品。原版材料与 CE 自定义物品分开统计：CE 物品不会凭借底层原版材质充当 `items` 材料，指定 CE 物品应写入 `ce-items`。检查只比较原版类型或 CE ID，不比较附魔、耐久、名称或药水效果。经验等级仅检查，不扣级；默认没有累计杀怪、累计提交、建筑检测或命令奖励。

条件在研究确认时重新检查。缺少 CE 或接口不可用时，配置了 CE 材料的节点会阻止研究并提示；默认路线全部使用原版材料。默认没有进度 ID 限制，自定义 `advancements` 前请核对本服进度实际存在。

研究点扣费、节点解锁和首次奖励作为一次存档事务保存。重复点击、退出重进或撤销后重研不会重复领取奖励；管理员 `grant` 不扣费用、不检查材料或等级等研究条件，但仍检查前置，并登记奖励历史而不发放研究点。`revoke` 不退款，也不清除首次奖励历史。

## CraftEngine 配方权限

默认树不会自动改动任何原版或 CE 配方。在自己的 CE 内容包中，为目标配方加入与节点权限一致的条件：

```yaml
# 配方条件列表，不满足权限条件的玩家不能使用该配方。
conditions:
  # 条件类型，固定为 permission。
  - type: permission
    # 与 boots 节点外层 permissions 完全一致。
    permission: litechtree.recipe.boots
```

完成 `boots` 后获得 `litechtree.recipe.boots`，无需 LuckPerms。本插件提供权限，CE 负责执行配方条件；需使用支持 `conditions` 的 CE 版本。不要把研究所需材料的唯一获取配方锁到该节点后面，例如把基础工作台或木棍配方锁在它们自己的研究后，造成材料自锁。

节点配方权限由本插件独占管理，未解锁时显式拒绝，包括 OP。不要交给其他权限插件同时控制，不要填写管理权限。多个节点共享同一权限时，任一节点解锁即可获得。`requirements.permissions` 是研究前的准入条件，与研究后授予的外层 `permissions` 用途不同。

## 配置与存档

- `config.yml`：后台保存周期、可选经验兑换比例。
- `messages.yml`：提示、节点状态、条件明细和界面文案，支持 MiniMessage 渐变与 RGB。
- `tree.yml`：章节、节点、条件、费用、首次奖励、权限和说明；每章 `slot` 范围 0~44，为 9 列 × 5 行，同章不可重复。
- `ui.yml`：当前预设、按钮与显示选项、各预设绘图参数。
- `ui-layout.yml`：与资源包配套的字体、坐标和样式签名，不应手工修改码位。
- `players/UUID.yml`：研究点、经验余数、解锁节点与首次奖励历史。损坏存档不会被空数据覆盖。

名称、说明、条件、费用、奖励与权限变更只需重载。节点 ID、所属章节、位置、图标、前置或节点集合变更后，须重建资源包和清单。删除配置节点不会删除历史解锁，恢复同名节点可恢复原状态；首次奖励历史同样保留。

存档先在后台原子写入，再在玩家所属线程应用状态和权限；失败保留原状态。正常停服会排空写队列，强制结束进程仍可能丢失尚未保存的经验。
