## 0.27.8 召唤无响应修复

停服备份后替换为 `LiPet-0.27.8-SNAPSHOT.jar` 并重启，执行 `/lipet status` 核对实际加载版本。旧版实体任务已受理却在执行前退休时，可能留下未完成的召唤 Future，使同一玩家的后续请求一直排队；`/lipet reload` 不重建玩家操作队列，所以不能代替这次换 Jar 和重启。

新版补全实体任务完成与召唤回滚分支，同步依赖错误和查询失败不再留下永久占位。命令与仓库等待超过 100 tick 时仅提示一次，`messages.yml -> pet-call-pending` 设为 `""` 可关闭；该提示不取消操作、不解锁正在进行的数据写入。

保留宠物数据库、管理员配置与 0.27.7 的骑乘修复，不需要清库或删除宠物。旧消息只补缺失节点和注释，自定义文本及空值不覆盖。默认兼容构建（Paper 1.21.11 API）与 Paper 26.2 Profile 各 306 项测试通过；同一成品已在 Paper 26.1.2 Build 70、26.2 Build 111 与真实 SQLite 验证失败回滚、队列继续运行及无需重载重试成功，26.2 狼骑乘回归也通过。未做真人客户端、真实 MEG 或 Folia 实服验证；详情见 [0.27.8 召唤无响应修复](更新日志-2026-09-01-召唤无响应修复.md)。

## 上一版 0.27.7 骑乘名牌与视角转向

停服备份后替换为 `LiPet-0.27.7-SNAPSHOT.jar` 并重启，执行 `/lipet status` 核对实际版本。已有 `nameplate.hide-while-ridden` 与其他自定义配置、注释保留：`true` 在骑乘时对所有玩家隐藏名称，下马恢复；`false` 继续显示。后续只调整这一开关可执行 `/lipet reload`。

## 上一版 0.27.6 货币名称配置与热重载

首次升级时停服备份后替换为 `LiPet-0.27.6-SNAPSHOT.jar`，保留原配置并重启一次。旧配置只补缺失节点与注释：`currency.playerpoints.display-name` 默认“点券”，`currency.vault.display-name` 默认“金币”，内置货币默认“宠物币”；管理员已有名称、注释与商品价格不覆盖。

完成升级后修改 `config.yml` 的三个 `currency.*.display-name`，执行 `/lipet reload` 并等待成功，再关闭并重新打开 `/lipet shop`、`/lipet itemshop` 即可。已经打开的菜单不会自动重绘。失败或被拒绝的并发重载不发布候选名称；服务器 ID、群组和内置货币初始余额仍按启动时读取。

默认构建与 Paper 26.2 Profile 各 216 项测试通过；同一 Jar 在 Paper 26.1.2 / 26.2 + PlayerPoints 3.3.5 完成服务端双商城 Lore、真实重载与扣款探针，未做真人客户端视觉测试。配置、步骤和完整验证见 [0.27.6 货币名称与热重载](更新日志-2026-08-31-货币名称重载.md)。

## 2. 安装

1. 将 `LiPet-0.27.8-SNAPSHOT.jar` 放入服务器 `plugins/` 目录。
2. 启动服务器一次，让插件生成默认配置。
3. 停服，编辑 `plugins/LiPet/` 下的配置文件。
4. 再次启动服务器。
5. 执行 `/lipet status` 检查状态。

需要使用 CraftEngine 自定义物品时，安装 CraftEngine 26.8.1 后可执行 `/lipet status <CE物品ID>` 验证生成与反向识别链路；未安装 CraftEngine 时原版物品功能仍可使用。

需要使用按等级解锁的外部技能时安装兼容的 MythicMobs 5.x，并在对应 `宠物类型/*.yml` 中启用技能规则。MythicMobs 为软依赖，不安装时其他宠物功能仍正常；执行 `/lipet status` 可查看挂钩状态。

单服推荐 SQLite。群组服推荐 MySQL，并按需开启 Redis 同步。

## 22. 升级建议

升级前：

1. 停服。
2. 备份 `plugins/LiPet/`。
3. 备份 SQLite 或 MySQL 数据。
4. 替换 Jar。
5. 启动服务器。
6. 执行 `/lipet status`。
7. 检查控制台是否有 LiPet 警告或错误。

LiPet 会补全新增配置节点，但不会覆盖已有自定义配置值。

升级到 `0.27.6` 必须首次替换 Jar 并重启，旧版 `/lipet reload` 不能加载新代码。后续仅修改货币名称无需再次重启，重载成功并重开菜单即可；`shop.yml` 继续使用 `INTERNAL`、`VAULT`、`PLAYERPOINTS` 支付 ID，`100.00` 价格格式和实际扣款不变。

升级到 `0.27.4` 后，`capture.yml` 和 `pet-types.yml` 会补入默认关闭的 CraftEngine 捕捉球与宠物食物案例。替换其中的 `yourpack:*` 完整 ID 并启用后执行 `/lipet reload`；关闭案例不会要求服务器安装 CraftEngine，也不会覆盖原有捕捉球和食物数值。

升级到 `0.27.2` 后，数据库中的 `bat`、`fox`、`minecraft:bat` 等旧原版类型 ID 会自动兼容到当前 `vanilla_<实体名>` 类型。插件还会为商城现有 10 种宠物创建缺失的独立 YML；已有文件、类型、数值和注释不会覆盖。

升级到 `0.27.1` 后，历史官方 `status-mythicmobs` 默认文本会自动加入技能类型数和规则数变量；服主自定义状态文本与注释保持不变。MM 失败技能新增退避与逐技能日志限频，不需要改现有技能规则。

升级到 `0.27.0` 后，旧宠物类型文件会增加一个带完整中文注释、`enabled: false` 的 MM 技能示例；它不会调用占位技能。配置真实技能名并启用后，执行 `/lipet reload` 即可生效。

从旧版升级时，如果 `宠物类型/` 尚不存在，插件会把 `pet-types.yml` 的旧 `types` 按类型拆成多个文件并保留注释；如果目录已经存在，则不会移动或覆盖，旧单文件格式仍可继续读取。

## 23. 构建

普通通用包：

```text
mvn clean package
```

Paper 26.2 编译检查：

```text
mvn -Ppaper-26.2 clean package
```

输出：

```text
target/LiPet-0.27.8-SNAPSHOT.jar
```
