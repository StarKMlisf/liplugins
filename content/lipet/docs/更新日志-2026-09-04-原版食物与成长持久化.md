# LiPet 0.27.11 原版食物与成长持久化修复

## 修复内容

### 原版宠物食物

- 全部默认可捕捉原版生物均有独立食物。烈焰人默认使用 `BLAZE_POWDER`（烈焰粉），狼使用骨头，猫使用鳕鱼，史莱姆使用黏液球，岩浆怪使用岩浆膏。
- 新安装生成的每个原版宠物 YML 都包含完整中文注释、开关、显示名、经验、治疗量、属性点和等级范围。
- 原版物种使用的不是熟牛肉时，会在该宠物文件内把继承的 `COOKED_BEEF` 设为 `enabled: false`，避免所有生物继续吃同一种公共食物。
- 升级旧服只扫描 LiPet 官方原版宠物 ID，且仅在文件完全缺少 `growth.foods` 时补全。只要管理员已写过该节点，原食物、数值、注释都会保留；自定义宠物文件不修改。

烈焰人生成示例：

```yaml
types:
  vanilla_blaze:
    growth:
      foods:
        COOKED_BEEF:
          enabled: false
        BLAZE_POWDER:
          enabled: true
          display-name: "烈焰粉"
          experience: 20
          healing: 6.0
          attribute-points: 0
          minimum-level: 1
          maximum-level: 0
```

### 等级、经验与重启持久化

- 同一只宠物正在写数据库时，后续战斗经验会进入下一批合并保存，不再为每次击杀单独提交一次完整宠物记录。
- 不同玩家的宠物仍可分别提交批次；每个玩家原有的召唤、回收、成长、加点和技能操作顺序保持不变。
- 后续的回收或关服保存必须等前面的经验批次完成，因此不会用旧活动会话覆盖刚获得的等级。
- 数据库 revision 冲突时最多重读最新记录并重试两次，不会直接把一批经验静默丢弃。
- 活动宠物按主人、宠物 ID 和实体 ID 建立的三份索引改为同一临界区校验及更新，避免只更新一部分索引。
- 战斗经验保存失败时记录宠物 ID，并向在线主人发送 `messages.yml -> pet-combat-experience-save-failed`；服主可修改文字，但不建议留空，以免再次表现成只有宠物币到账。

经验消息按实际已合并的总数发送一次；一次批次跨越多级时，升级宠物币也按本批实际升级数一次结算。

## 配置与升级

1. 停服并备份 `plugins/LiPet/` 与数据库。
2. 替换为 `LiPet-0.27.11-SNAPSHOT.jar` 后完整启动服务器。
3. 检查控制台“为多少个原版宠物文件补全食物”的日志。
4. 打开 `plugins/LiPet/宠物/原版宠物/烈焰人.yml`，确认 `BLAZE_POWDER` 已生成；若该文件原来已有 `growth.foods`，插件会保留原配置，不会强改。
5. 执行 `/lipet status`，再用测试宠物刷经验并正常停服、启动，核对等级和经验。

`/lipet reload` 可以重读已经存在的食物配置，但旧 Jar 没有新迁移与经验批处理代码；升级必须替换 Jar 并完整重启一次。
