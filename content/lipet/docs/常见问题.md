# 常见问题

> 本页从 LiPet `0.27.6-SNAPSHOT` 完整 Wiki 同步整理；需要连续查阅全部功能时，请返回 [LiPet 完整 Wiki](../home/)。

## 21. 常见问题

### 重启后宠物不见了

检查 `storage.type`。当前推荐：

```yaml
storage:
  type: "SQLITE"
```

旧版 `MEMORY` 配置会自动迁移为 SQLite。生产服请备份 `plugins/LiPet/lipet.db` 或 MySQL 数据库。

### 插件显示 plugin is disabled

不要只看 `/lipet` 命令报错。需要查看服务器启动时最早的 LiPet 错误堆栈。

常见原因：

- 配置格式错误。
- 材质或实体类型拼错。
- 数据库连接失败。
- 运行时依赖无法下载。

### No sound found with the name UI_TOAST_CHALLENGE

这是旧配置里的无效音效名。`0.25.3+` 已修复：插件会自动回退为 `ENTITY_PLAYER_LEVELUP`，不再因此禁用。

### CraftEngine 图标显示屏障或商品无法发放

执行 `/lipet status <CE物品ID>`。若没有显示“全链路自检通过”，请确认 CraftEngine 已完成重载、配置使用完整 `namespace:item_id` 且该 ID 存在。GUI 会显示中文屏障占位，商城会自动退款，不会错误发放同底材原版物品。

### Thread LiPet-SQLite failed main thread check

这是 `0.26.0` 的数据库回调错误。升级到 `0.26.1+` 后，属性加点、喂养、召回和收回不再从 SQLite 线程查询区块实体。若升级后仍看到该堆栈，请先确认服务器实际加载的 Jar 版本不是旧版。

### 提示已收回，但可驯服宠物仍在

这是旧版本把狼、猫、鹦鹉等实体同时交给原版驯服系统管理造成的生命周期冲突。升级到 `0.26.2+` 后，收回会先清理原版驯服/坐下状态，并额外处理左右肩实体。升级后首次召回旧鹦鹉时会自动解除原版肩部行为。

### 宠物背包没有保存

背包在关闭界面时保存。如果服务器崩溃，最后一次打开中的背包可能来不及保存。生产服建议定期备份数据库。

### 信号棒没有反应

确认：

- 物品由 `/lipet signalstick` 发放。
- 玩家当前有已召唤宠物。
- 没有其他插件取消右键交互事件。

### 商城购买失败

检查：

- 玩家余额是否足够。
- `shop.yml` 中的 `pet-type` 是否存在且启用。
- 玩家是否已经拥有该类型宠物。
- Vault 模式下是否安装了 Vault 和经济插件。

### 商城还显示“100.00 PlayerPoints”，修改名称没有效果

旧版 PlayerPoints 名称由代码固定，且内置货币名称在启动时被缓存。先停服换入 `LiPet-0.27.6-SNAPSHOT.jar`，重启一次并确认实际加载的版本，再修改 `plugins/LiPet/config.yml`：

```yaml
# 合并到 config.yml 已有 currency 节点，不要覆盖整份配置。
# 这里只改显示名称，shop.yml 的支付 ID 和商品价格保持不变。
currency:
  # shop.yml 使用 currency: INTERNAL 的商品。
  internal:
    # 非空单行文本，支持 MiniMessage；默认“宠物币”。
    display-name: "宠物币"
  # shop.yml 使用 currency: VAULT 的商品，需安装 Vault 与经济插件。
  vault:
    # 非空单行文本，支持 MiniMessage；默认“金币”。
    display-name: "金币"
  # shop.yml 使用 currency: PLAYERPOINTS 的商品，需安装 PlayerPoints。
  playerpoints:
    # 非空单行文本，支持 MiniMessage；默认“点券”，可按需修改。
    display-name: "点券"
```

执行 `/lipet reload` 并等待成功，关闭原商城后重新执行 `/lipet shop` 或 `/lipet itemshop`。已有菜单不会自动重绘；重载失败或并发重载被拒绝时保留原名称，修正控制台提示的问题后再重载。

检查商品 Lore 是否使用 `<price> <currency>`。如果服主自定义 Lore 直接写了 `PlayerPoints`，需要改成 `<currency>` 才能跟随名称配置。`shop.yml` 中的货币 ID 仍填写 `INTERNAL`、`VAULT` 或 `PLAYERPOINTS`，不能填写“点券”。价格 `100.0` 仍显示为 `100.00`，默认完整文字变成 `100.00 点券`，扣款金额和 PlayerPoints 整数要求都不变。

如果显示的是大写 `PLAYERPOINTS` 或 `VAULT`，请先用 `/lipet status` 检查对应前置插件挂钩。不可用或未知提供器仍显示原 ID 供排查，不能仅靠修改名称恢复支付。

升级只补缺失名称和注释，已有自定义值会保留。名称热更也不会改变 `server.id`、群组 `server.group` 或内置初始余额 `currency.internal.initial-balance`，这些仍按启动时读取。

### 宠物币只能消费，无法获取

升级到 `0.26.6+` 后检查：

- `rewards.yml` 顶层 `enabled` 以及对应玩法的 `enabled` 是否为 `true`。
- 玩家是否拥有 `lipet.command.daily` 权限。
- 战斗必须由当前召唤的宠物完成最后一击；玩家自己击杀不会获得宠物战斗奖励。
- 对应玩法是否已经达到 `daily-limit`；每日额度按 `reset-time-zone` 的零点重置。
- 数据库异常时查看控制台中的 `LiPet-Rewards` 错误，并确认当前 Jar 确实为新版本。
