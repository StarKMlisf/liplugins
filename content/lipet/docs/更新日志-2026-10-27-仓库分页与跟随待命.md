# LiPet 2.3.15 · 仓库分页与跟随待命

发布日期：2026-10-27。

## 宠物仓库分页

修复宠物数量超出仓库单页格子后，后续宠物无法在界面中查看的问题。仓库新增上一页、下一页和页码，宠物按页显示。分页不改变宠物所有权或存档，也不提高每种宠物的拥有数量限制。

每只宠物继续使用原来的名称、说明、点击操作和独立图标，支持已有的 CraftEngine 物品图标。升级时保留管理员的 GUI 标题、布局、图标与自定义按钮，只补齐缺失的分页配置。

### 配置位置与翻页行为

配置在 `gui.yml` 的 `warehouse.pagination` 下；旧配置会自动补齐缺失项。

| 配置节点 | 用途 | 默认值 |
| --- | --- | --- |
| `previous.slot` | 上一页首选槽位 | `45` |
| `next.slot` | 下一页首选槽位 | `50` |
| `indicator.slot` | 页码图标首选槽位 | `48` |
| 各按钮的 `material` | 原版材质或 CE 完整物品 ID | 翻页为 `ARROW`，页码为 `BOOK` |
| 各按钮的 `name` / `lore` | MiniMessage 名称与说明 | 显示页码与宠物数量 |

仓库标题和三个分页按钮支持 `<page>`（当前页，从 1 开始）、`<pages>`（总页数，至少 1）和 `<pet_count>`（宠物总数）。默认每页 21 只，由 `warehouse.pet-slots` 的实际可用格子数决定；例如 50 只宠物分为 3 页。

首选槽位取值为 `-1` 至 `53`。设为 `-1`、超出当前仓库大小或与已有按钮冲突时，自动选择其他可用格子。分页保留已有导航和自定义按钮；必要时减少本页宠物格子，把余下宠物放到后续页。空间不足时可以省略页码图标，但至少要留出两个翻页按钮和一个宠物格子，否则会提示布局空间不足。

宠物使用稳定顺序排列，喂食、召回或自动存档不会因为更新时间变化而重新排序。第一页的“上一页”、最后一页的“下一页”仍显示图标，但不会越界翻页。返回仓库时记住本次在线期间最近浏览的页；宠物数量减少后，自动回到仍然存在的有效页。玩家关闭或切换界面后，已过期的翻页查询不会重新打开旧仓库。

## 跟随到位后待命

宠物跟随到主人附近后停止自主闲逛；刚召唤在主人附近、尚未开始追赶时也会进入待命。主人走远后，宠物恢复跟随。

本项无需增加配置，继续使用每只宠物的 `behavior.follow-enabled`、`behavior.follow-distance` 和 `behavior.stop-distance`。默认进入 3 格停止范围后待命，超过 10 格重新追赶；已有配置值保持不变。

待命保留地面和水中的正常垂直物理，仅清除 LiPet 自己施加的飞行速度，不用反复传送把宠物固定在一点。战斗、骑乘、牵引和坐下仍由各自原有逻辑处理。外部模型动画或第三方 MM 技能主动造成的位移不等同于原版闲逛，本次不承诺阻止这类位移。

## 更新方式

正常停服后备份数据，将旧 LiPet Jar 移到 `plugins` 目录外，再放入 `LiPet-2.3.15.jar`。保留原配置、数据库和资源包，启动时确认加载版本为 2.3.15。无需重新创建宠物，也不要同时保留两个 LiPet Jar。

修改 GUI 配置后执行 `/lipet reload` 并重新打开仓库。跟随距离沿用现有配置；不要为本次更新覆盖整份宠物配置。
