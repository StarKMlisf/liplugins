# 2026-10-03 · LiPet 2.2.1 · MySQL 持久化修复

修复 MySQL 模式下“新宠物显示保存成功，断线或重启后却消失”的一条已复现路径。问题来自被动技能书学习/升级后连接遗留的手动提交状态，与主动技能自动释放无关。

## 触发条件与表现

被动技能书调用 `learnSkill` 时会开启事务。旧版在提交或回滚后将连接归还连接池，但没有恢复自动提交状态。后续捕捉或创建宠物借到同一连接时，`INSERT` 虽然返回成功，实际写入仍未提交。

同一连接能读到这只宠物，独立连接却读不到；连接断开、连接池关闭或后续事务回滚时，新记录消失。连接池有多个连接时，取到哪条连接决定是否遇到问题，因此会表现为偶发丢失。既有宠物的属性更新和背包写入也可能受未提交事务影响，读取还可能停留在旧事务快照。

此次已用旧版 2.2.0 成品 Jar 和真实 MySQL 8.0.45 稳定复现：先保存宠物 A，再学习被动技能，随后保存宠物 B；B 返回 `CREATED`，同一连接可见、独立连接不可见，关闭并重开仓库后 B 消失，A 仍在。

## 修复内容

- 归还连接时发现 `autoCommit=false`，先执行 `rollback`，再恢复 `autoCommit=true`。不能直接开启自动提交，以免把上一次操作遗留的失败事务意外提交。
- 恢复连接初始的只读状态和事务隔离级别，并清除旧警告；新建连接借出前也校正事务状态。
- 回滚或任何状态恢复失败时，立即关闭并丢弃该物理连接，后续操作使用新连接。
- 连接池关闭与连接归还入队互斥，避免关闭后仍遗留空闲连接；建连途中遇到关闭也不会继续借出新连接。

不更改数据库表结构，不迁移宠物记录，不覆盖管理员配置。112 项主动技能、每宠三槽、CE 配方捕捉和已有模型动画功能保持原有配置。

## 升级与已有数据
