# LiPet 更新日志 · 2026-08-28

适用版本：`0.26.12-SNAPSHOT`

本次更新加入管理员跨玩家宠物发放与收走指令，并修复 Residence 等领地禁止生物生成时，宠物无法出现却可能残留名字的问题。

## 1. 宠物 give / take 指令

新增：

```text
/lipet give <玩家|-all> <宠物类型> [宠物名称]
/lipet take <玩家|-all> <宠物名称|UUID|宠物类型|-all>
```

示例：

```text
/lipet give Steve wolf 小狼
/lipet take Steve 小狼
/lipet take Steve wolf
/lipet give -all cat
/lipet take -all cat
/lipet take Steve -all
```

- 玩家名称支持不区分大小写匹配，目标可以离线，但必须仍有 Bukkit 玩家档案。
- 完整 UUID 可直接定位数据库玩家，即使本地 `playerdata` 已被清理也可使用。
- 第一个 `-all` 包含服务器全部已知离线玩家与当前在线玩家，并按 UUID 去重。
- `give` 的宠物类型必须存在且已启用；省略名称时使用类型默认显示名。
- 每名玩家对同一宠物类型仍只能拥有一只；已有同类型或同名宠物时安全跳过。
- `take` 支持宠物名称、宠物 UUID、宠物类型 ID；第二个参数使用 `-all` 时收走该目标的全部宠物。
- 收走已召唤宠物时会清理活动会话、实体、ModelEngine 模型和双行名牌；已收回或离线玩家的宠物直接从持久化数据删除。
- 全服操作在后台逐个玩家、逐只宠物执行，避免瞬间向 SQLite / MySQL 提交大量并发写入。
- 单个目标失败不会中断后续玩家；完成后报告玩家总数、命中、删除、跳过和失败数量。
- Tab 补全包含 `-all`、服务器已知玩家名、宠物类型和当前已缓存的宠物名称。

权限：

```text
lipet.admin.pet.give
lipet.admin.pet.take
```

两项权限默认仅 OP 拥有，并已加入 `lipet.admin` 子权限。全部反馈文本位于 `messages.yml`，可使用 MiniMessage 自定义。

## 2. Residence / 领地保护内召唤

旧流程在调用世界生成后才写入宠物标记。Residence 等插件会先把 `CUSTOM` 生物生成事件取消，LiPet 因而无法在事件阶段识别这是自己的宠物；后续流程还可能继续创建 TextDisplay，最终表现为只有名字、没有宠物实体。

新流程：

1. 使用 Bukkit `World#spawn` 的生成前回调写入宠物 UUID 与宠物类型 PDC。
2. 使用 `CreatureSpawnEvent.SpawnReason.CUSTOM` 触发标准 Bukkit 生成事件。
3. LiPet 在 `HIGHEST` 优先级检查事件，只对已取消且带 LiPet 标记的实体解除取消。
4. 普通生物、刷怪笼生物、其他插件实体和没有 LiPet 标记的 `CUSTOM` 实体仍然遵守领地保护。
5. 生成返回后再次检查实体是否有效且存活；失败时立即回滚，不挂载模型、不启用 AI，也不创建宠物名牌。

`plugin.yml` 已将 Residence 声明为软依赖，用于稳定加载顺序。未安装 Residence 时不影响 LiPet 启动。

## 3. 升级步骤

1. 停服并备份 `plugins/LiPet/` 与 SQLite / MySQL 数据。
2. 删除旧 LiPet Jar，只保留 `LiPet-0.26.12-SNAPSHOT.jar`。
3. 启动服务器，等待 `messages.yml` 自动补齐新指令文本。
4. 给管理组按需授予 `lipet.admin.pet.give` 与 `lipet.admin.pet.take`。
5. 执行 `/lipet give <测试玩家> wolf 测试宠物`，确认目标仓库出现宠物。
6. 依次使用名称、类型 ID 和 UUID 执行 `/lipet take`，确认只删除匹配宠物。
7. 在 Residence 禁止生物生成的领地内召唤宠物，确认实体、模型、AI 和双行名牌同时出现。
