# 0.27.28 · 单宠名牌、战斗跟随与骑乘输入兼容

## 单宠物 nameplate

旧版只读取 `pet-types.yml` 根节点的全局 nameplate，单宠物文件中的设置被忽略。现在每种宠物可单独覆盖，未填写项继承全局设置，`/lipet reload` 会刷新已经召唤的宠物。

```yaml
types:
  long_1:
    # 名牌配置与 behavior、model 同级。
    nameplate:
      # 是否显示双行名牌；false 使用原版单行名称。
      enabled: true
      # 长度 1-512，支持 MiniMessage、<owner_name>、<pet_name>、<level>。
      owner-line: "<gray>主人：</gray><white><owner_name></white>"
      # 垂直偏移，范围 -2.0 至 4.0。
      vertical-offset: 0.30
```

字体阴影、背景、透明度、显示距离、行宽及骑乘时隐藏开关也支持单宠覆盖。为兼容已写错层级的文件，同时读取 `behavior.nameplate`；若两个位置同时存在，正式 `nameplate` 同名字段优先。建议整理为上述标准格式。

## 战斗与跟随优先级

旧版发现战斗目标后直接跳过跟随，宠物会持续追打敌人而不检查主人距离。现在超过 `behavior.follow-distance` 就清除战斗目标并返回，回到 `stop-distance` 以内才重新允许接战。返回途中，受击反击和原版目标事件不能重新把宠物留在战场。

超过 `teleport-distance` 时仍采用安全召回。主人腾空时不向危险空中落点强行传送，但会继续追赶，不再在原地等待。关闭跟随、拴绳、坐下或骑乘时保留相应控制意图。

## 骑乘验证范围

模型驾驶座新增 Bukkit 当前按键同步，减少对 ModelEngine 特定协议监听的依赖；骑乘时暂停 LiPet 周期技能，避免与驾驶控制互相干扰。依旧使用 ModelEngine 的驾驶座和移动控制，不改写第三方模型骨骼。

已对通用测试蓝图分别检查 MM 生成载体和原版狼套模型路径。用户的 `pet_fire_dragon_fire`、`pet_fire_dragon_soulfire` 蓝图与对应 MM Mob/技能文件未提供，因此不能把通用模型测试视为这两只龙的实机验收。若仍无法骑乘，需要对应模型包、MM 配置以及异常视频或日志继续定位。

## 两份龙配置的核对

- `龙.yml` 的 nameplate 层级正确，旧版不支持单宠覆盖是其不生效的原因。
- `龙2.yml` 的 nameplate 与 mythic-skills 都位于 behavior 下。修正版把两者移到类型根节点，并关闭未替换的 `ChangeMeSkill` 示例；请填入真实技能名后再启用。
- 两份文件的 1 级和 2 级模型 ID 相同，因此升级到 2 级不会改变外观；这不影响固定模型的使用。
- `inherit-defaults: false` 会关闭公共宠物属性、食物与成长的继承。未擅自改动该选择、模型 ID、速度或解锁等级。

提供的是独立修正版文件，下载目录中的原文件和正式服现有宠物配置均保留。替换配置时不要同时保留相同类型 ID 的两份 YML。

## 更新

正常停服后替换 Jar 再启动；不要用 PlugManX 热卸载来替换程序。配置修改使用 `/lipet reload`。完整测试结果及未覆盖的客户端场景记录于本次交付验证记录。
