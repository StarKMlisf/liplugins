# LiPet 0.27.5 · 等级模型、随机捕捉与捕捉球商店

发布日期：2026-08-30；成品：`LiPet-0.27.5-SNAPSHOT.jar`。

## 新增功能

- `model.levels` 为每种宠物设置模型等级门槛，选择不超过当前等级的最高档；未配置时继续使用旧固定模型。
- 升级和实体恢复时按当前等级应用模型，避免同一模型重复叠加；切换失败时尝试恢复旧模型。
- `capture.yml` 新增原版捕捉随机属性，默认四属性独立均匀抽取 0–5 的整数，也可关闭或调整范围。
- 随机值在成功捕捉创建时写入宠物数据，初始生命按体质计算；指令发放、宠物商城购买和既有宠物不重新随机。
- `shop.yml` 道具商品可用 `item.capture-ball` 引用 `capture.yml` 中的捕捉球，发放物品带有 LiPet 捕捉标记并保留 CraftEngine 元数据。
- 新增普通捕捉球商品案例；球类型不可用时不扣款，交易期间失效则退款。

## 升级与配置

停服备份 `plugins/LiPet/` 和数据库后替换 Jar。首次启动只补缺失配置节点和中文注释，不覆盖已有商品、宠物模型和自定义属性。

等级模型必须引用服务器已安装的 ModelEngine 蓝图。`a`、`b` 是示例 ID，插件不附带这些模型或客户端资源包。

完整操作与配置见 [等级模型、随机属性与捕捉球商店](等级模型与捕捉球商店.md)。

## 验证边界

默认构建与 Paper 26.2 API Profile 各 206 项测试通过，失败、错误、跳过均为 0；成品仅包含 LiPet 自身类，使用 Java 21 字节码。

同一 Jar 在 Paper 26.2 Build 111 与 Paper 26.1.2 Build 70 + Java 25 + CraftEngine 26.8 上完成启动、重载、普通/CE 捕捉球标记和 CE 原始身份检查。真实 SQLite 创建、读取和重启检查确认四属性 `3,2,2,3` 保持不变，体质对应初始生命为 `28.0`。此为服务端探针验证，不等于玩家完整购买/右键捕捉实测。

Jar 大小：`813533` 字节；SHA-256：`55099709368BE40521E2BF31CD57EE6322F3FF46ABA16B3B443F94003E791463`。

跨版本注意：26.2 自动生成的高版本生物配置不能原样用于 26.1.2，例如 `SULFUR_CUBE` 在低版本不存在。26.1.2 验证使用由该版本重新生成的原版类型目录，并保留捕捉配置及 SQLite 数据。
