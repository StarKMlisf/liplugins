# 成长、属性与喂养

## 0.27.25 血量刷新修复

重载、区块恢复、升级和加点保留当前实体血量；生命上限降低时只做钳制。首次召唤仍恢复保存血量。喂食保存成功后追加本次治疗，不把保存前的血量覆盖回实体。死亡待保存期间不继续成长，详见 [逐项排查报告](../audit-2026-09-06-lifecycle/)。

## 死亡扣级（0.27.24）

默认死亡扣 1 级、最低保留 1 级；实际掉级清空当前级经验，并扣回相应升级属性点，优先扣未分配点数，不足部分按当前四维比例扣回。关闭惩罚或达到下限时不扣成长数据。四维没有逐点来源区分，因此可能扣到捕捉或食物增加的点数，详见 [配置和扣点规则](../changelog-2026-09-06-death-penalty/)。

## 0.27.20 喂食冷却

`config.yml -> feeding.cooldown-seconds` 控制同一只宠物两次成功喂食的间隔，默认 `1.0` 秒，支持 `0-60` 的小数；`0` 表示关闭。修改后执行 `/lipet reload` 生效。

冷却只在食物合法、等级允许且会产生经验、治疗或属性点时开始。冷却中会显示剩余秒数且不扣物品；非主人、无效食物、无效果及数据库失败不消耗冷却，保存失败会撤销占位。

## 0.27.19 属性加点与属性归属修复

加点遇到短暂 revision 冲突时会重新读取权威档案并最多重试两次，避免一次竞争就显示“提升失败”。力量只增加攻击、暴击伤害与少量吸血；暴击率、移动速度和闪避率由敏捷增加。自定义属性动作兼容大小写，没有点数与动作格式错误分别显示独立中文提示。详见 [0.27.19 更新日志](../changelog-2026-09-05-attribute-allocation/)。

## 0.27.18 连续属性加点刷新修复

数据库确认加点保存成功后，界面直接使用这次返回的权威宠物档案刷新，不再发起一次可能复用较早结果的全宠物查询。四维加一、剩余点数扣除、revision 乐观锁与活动实体属性刷新规则不变。该修复需要停服替换 Jar 并完整启动。

CraftEngine 食物仍按完整 ID 精确匹配；`0.26.14` 起同一 CE 物品桥还覆盖捕捉球、技能书、信号棒、商城与 GUI。完整配置见 [CraftEngine 完整物品挂钩](../craftengine-integration/)。

`0.27.0` 起，服主可以在每种宠物自己的 YML 中配置 MythicMobs 技能解锁等级。宠物升级到 `unlock-level` 后自动获得施放资格；超过解锁等级时，还可按 `power-per-level` 继续增强传给 MM 的技能威力。完整示例见 [配置说明](../configuration/) 与 [本次更新日志](../changelog-2026-08-29-mythicmobs-level-skills/)。

## 0.27.17 风弹喂食冲突修复

主手持风弹右键自己的旋风人即可喂食，无需更换食物或改键。插件会阻止这次喂食附带的原版物品使用，副手回退也不会额外发射。成功喂食只扣一份，创造模式不扣除；合法食物喂食失败时不会改为发射。

普通朝空处投掷保持正常；只有该宠物 `growth.foods` 接受的物品才登记喂食保护。旧服食物及经验数值不会被修改。Paper 26.2 服务端包处理器实测旧版 8 颗变 6 颗，新版 8 颗变 7 颗，经验均为 4；新版无风弹实体。详情见 [0.27.17 更新日志](../changelog-2026-09-05-food-use-conflict/)。

## 0.27.14 原版宠物专属食物校准

Paper 26.2 的 87 种默认可捕捉原版宠物已逐项复核；有原版食物标签或同族规则时，优先使用原版接受的物品。枯骆驼使用兔子脚，猪灵类使用熟猪排，硫磺魔方使用黏液球，狼使用肉类，猫使用生鱼，僵尸马使用红色蘑菇，僵尸鹦鹉螺使用河豚。没有原生喂食机制的生物继续使用生态、掉落物或修复材料作为主题食物。

旧服已有 `growth.foods` 不会被覆盖。管理员需要按 [0.27.14 更新日志](../changelog-2026-09-04-vanilla-pet-food-alignment/) 手动替换旧食物节点，再执行 `/lipet reload`；每次经验继续建议设为 `4`。

## 0.27.13 默认喂食与战斗经验平衡

所有官方默认食物现在每次提供 `4` 点经验。默认击杀经验为 `round(5 + 目标最大生命 × 0.5)`：最弱目标约 `6` 点，20 点生命的常见目标为 `15` 点，因此让宠物战斗会比连续喂普通食物成长更快。附魔金苹果继续提供治疗和属性点，但经验也为 `4`。

旧服已有 `growth.foods` 不会被覆盖。要使用新平衡，请手动把对应食物的 `experience` 改成 `4` 后执行 `/lipet reload`。详情见 [0.27.13 更新日志](../changelog-2026-09-04-feeding-experience-balance/)。

## 0.27.11 原版食物与战斗经验

全部默认可捕捉原版生物都有独立食物；烈焰人使用烈焰粉，狼使用骨头，猫使用鳕鱼，岩浆怪使用岩浆膏。新安装直接生成完整中文配置；旧官方文件仅在完全缺少 `growth.foods` 时补全，管理员已有食物规则和自定义宠物文件不覆盖。

同一只宠物在数据库写入期间继续获得的战斗经验会合并为下一批保存，并保持玩家操作顺序。回收和关服保存会等待前面的经验批次，数据库 revision 冲突会重读最新记录后重试，避免多人刷级时经验长时间不动或重启后读回旧等级。详情见 [0.27.11 更新日志](../changelog-2026-09-04-food-growth-persistence/)。

## 0.27.10 敏捷与最终速度

宠物实体、跟随导航、战斗追击、GUI 的 `<speed>` 和 `%lipet_active_speed%` 现在都使用“基础速度 + 敏捷 + 速度技能”的同一个最终值。成长刷新后会重新应用技能效果，不再把迅捷技能覆盖掉。速度最多显示三位小数；默认基础速度 `0.25` 时，敏捷 1 显示 `0.255`，不是四舍五入后的 `0.3`。

## 0.27.5 新增配置与行为

原版捕捉宠物默认四项初始属性各随机 0–5，范围可配置；既有宠物、商店购买和管理员发放不重新随机。`model.levels` 可设置 1 级模型 a、2 级模型 b，喂养或战斗升级后自动切换。

完整示例见 [等级模型、随机属性与捕捉球商店](等级模型与捕捉球商店.md)。

## 9. 属性与成长

核心属性：

- 力量：增加攻击伤害
- 体质：增加生命与恢复
- 防御：增加伤害减免
- 敏捷：增加移动速度，并影响闪避等衍生属性

衍生属性：

- 最大生命
- 攻击伤害
- 伤害减免
- 暴击率
- 暴击伤害
- 闪避
- 击退抗性
- 吸血
- 生命恢复

成长配置位置：

```yaml
growth:
  maximum-level: 50
  base-experience: 100
  experience-per-level: 25
  attribute-points-per-level: 3
```

宠物可通过喂食和战斗获得经验。升级后获得自由属性点，玩家可在 GUI 中加点。

属性与宠物状态的中文名称位于 `messages.yml`：

```yaml
labels:
  unknown-pet: "未知宠物"
  attributes:
    strength: "力量"
    vitality: "体质"
    defense: "防御"
    agility: "敏捷"
  pet-states:
    stored: "已收回"
    active: "已召唤"
    transferring: "转移中"
    dead: "复活冷却"
    disabled: "已禁用"
```

属性加点消息可使用完整上下文变量，常用变量包括 `<pet_name>`、`<attribute>`、`<attribute_key>`、`<previous_value>`、`<value>`、`<previous_points>`、`<points>`、`<strength>`、`<vitality>`、`<defense>` 和 `<agility>`。`<attribute>` / `<attribute_name>` 是中文显示名，`<attribute_key>` 保留 `STRENGTH` 等稳定英文键，适合动作和外部插件。

## 10. 喂食

食物配置在对应的 `宠物/**/*.yml` 中；旧 `pet-types.yml` 写法继续支持。烈焰人默认规则为 `growth.foods.BLAZE_POWDER`，并在本类型内关闭继承的 `COOKED_BEEF`。公共或自定义食物写法：

```yaml
foods:
  # 旧版 Bukkit Material 写法继续支持。
  COOKED_BEEF:
    enabled: true
    display-name: "熟牛肉"
    experience: 4
    healing: 6.0
    attribute-points: 0
    minimum-level: 1
    maximum-level: 0

  # CraftEngine 物品必须填写完整 namespace:item_id。
  # 节点名只是管理员自定别名；使用 item-id 后也完整支持含点号的合法 ID。
  craftengine_example:
    enabled: false
    item-id: "yourpack:pet_food"
    display-name: "灵契宠物粮"
    experience: 4
    healing: 8.0
    attribute-points: 0
    minimum-level: 1
    maximum-level: 0
```

规则：

- 玩家手持配置的原版或 CraftEngine 食物右键自己的宠物即可喂食。
- 官方默认 `experience` 为 `4`，低于默认战斗经验；管理员仍可配置其他非负数。
- 把案例中的 `item-id` 换成真实 CE ID，再将 `enabled` 改为 `true`；关闭案例不会参与识别、扣除或信息界面展示。
- CraftEngine 物品按完整自定义 ID 精确识别；即使多个物品都以 `PAPER` 为底材，也只会匹配配置的那一个。
- 简单 CE ID 可直接作为节点名，例如 `'default:pet_biscuit':`；ID 含 `.` 时请使用普通节点别名并填写 `item-id`。
- `CraftEngine` 是可选软依赖。未安装时原版食物仍可使用，CE 食物配置会保留但不会匹配。
- 修改食物规则后执行 `/lipet reload` 即可生效；CraftEngine 自身重载物品后无需重启 LiPet，因为插件不会缓存物品实例。
- 不符合等级限制时不会消耗食物。
- 没有产生回血、经验或属性点效果时不会消耗食物。
- 数据保存失败时会退还食物。

## 17. 技能书

发放：

```text
/lipet skillbook <技能> [数量] [玩家]
```

默认技能：

- `power`：攻击强化
- `vitality`：生命强化
- `agility`：速度强化

玩家右键自己的已召唤宠物学习技能。技能达到最高等级后不会继续消耗技能书。
