# LiPet 更新日志

## 0.29.1 · 主动索敌

空闲宠物现在可主动攻击附近可见敌对怪物，默认扫描范围 8 格；排除玩家、宠物、驯服生物及部分中立生物。坐下、骑乘、牵引、返回主人时不索敌，主人走远仍优先跟随。公共及独立宠物配置支持 `behavior.auto-attack.enabled/radius`，配置重载可生效。

## 0.29.0 · 品质、性格与闪光

新捕捉宠物可获得五档品质、可配置性格和稀有闪光。成长倍率与名称随档案保存，
召回、重载和重新读取存档不重抽，旧宠物保持原数值。仓库、详情、名牌与 PAPI 均可显示。
新增 traits.yml；材料进化、探索派遣留待后续批次。
详见本次品质、性格与闪光更新文档。

## 0.28.0 · 骑乘、命名与多行名牌

原版骑乘新增自动迈步和 LOOK/MOVEMENT 朝向；ModelEngine 保留独立驾驶控制。
新增 naming.yml 命名规则与 nameplate.lines 多行排版，兼容已有配置和名字。
0.28.0 为扩展开发第一批；品质/性格/闪光已在 0.29.0 补充，材料进化与探索派遣仍待后续。
配置说明见本次更新文档。

## 0.27.29 · 跟随与模型骑乘稳定性

地面宠物在主人附近停靠，减少贴身重叠；脱战返回不再反复重置路径。
模型虚拟座位跨 Folia 区域时保留骑乘判断，暂停不安全的读取；减少骑乘时名牌重复刷新。
不新增必填配置，具体行为及验证范围见本次更新说明。

## 0.26.8：ModelEngine / MEG 模型重叠修复

使用 ModelEngine 模型后，LiPet 仍然需要一个原版实体承载 AI、寻路、属性和交互。旧实现没有可靠隐藏这个载体，因此会出现模型和原版宠物同时显示。

本次更新加入：

- 使用 ModelEngine 载体可见性接口隐藏原版实体外观，不使用隐身药水伪装。
- 隐藏外观不会关闭宠物 AI、感知、寻路和战斗能力。
- 重复召唤、区块重新加载和运行状态恢复时复用已有模型，避免重复叠加。
- `/lipet reload` 后刷新已召唤宠物的模型配置。
- 修改模型 ID 时，先卸载本轮运行期记录的旧模型，再挂载新模型。
- 模型载体隐藏和模型碰撞箱覆盖可以分别控制。

推荐配置：

```yaml
types:
  wolf:
    model:
      provider: "MODEL_ENGINE"
      id: "magecat"
      # 隐藏原版载体外观，但保留 LiPet AI 与寻路。
      hide-base-entity: true
      # 使用 ModelEngine 蓝图碰撞箱。
      override-hitbox: true
```

如果仍然出现原版宠物：

1. 确认 `provider` 为 `MODEL_ENGINE`。
2. 确认 `hide-base-entity: true`。
3. 执行 `/lipet reload`，再重新召唤宠物。
4. 检查 ModelEngine 是否为支持当前 Paper 26.x NMS 的更新构建。

## 0.26.9：CraftEngine 自定义物品喂食

宠物食物现在同时支持：

- 原版 Bukkit Material，例如 `BEEF`、`COOKED_BEEF`。
- CraftEngine 完整自定义物品 ID，例如 `default:pet_biscuit`。
- ID 中含点号的 CraftEngine 物品，例如 `my.pack:pet.food`。

配置示例：

```yaml
types:
  wolf:
    foods:
      beef:
        material: "BEEF"
        display-name: "生牛肉"
        experience: 20
        healing: 6.0

      pet-biscuit:
        # 必须填写完整命名空间 ID，不能只写 pet.food。
        item-id: "my.pack:pet.food"
        display-name: "灵宠饼干"
        experience: 35
        healing: 8.0
        attribute-points: 0
        minimum-level: 1
        maximum-level: 0
```

识别规则：

- CraftEngine 物品按完整 ID 精确匹配，不按底材 `Material` 猜测。
- 即使 CE 物品和原版物品都使用同一种底材，也只会消耗配置中指定的物品。
- 简单 ID 可以直接作为食物节点名；ID 含 `.` 时使用普通节点名并填写 `item-id`。
- 未安装 CraftEngine 时不会禁用 LiPet，原版食物继续正常使用。
- CraftEngine 重载物品后无需重启 LiPet；插件每次交互都会读取当前物品 ID，不缓存旧物品实例。
- 不满足等级要求、没有产生有效效果或数据保存失败时，不会吞掉玩家物品。

## 0.26.10：取消 `/lp` 指令别名

LiPet 现在只注册 `/lipet` 主指令。

已移除：

- `/lp`
- `/lipet:lp`

保留：

- `/lipet`
- Bukkit 命名空间指令 `/lipet:lipet`
- 原有全部 `/lipet` 子指令、权限和 Tab 补全

这样不会再与 LuckPerms 等权限插件常用的 `/lp` 主指令发生冲突。旧菜单、NPC 或脚本如果仍在执行 `/lp`，需要改成 `/lipet`。
