# LiPet 0.29.5 · 监守者宠物主人保护

## 问题与处理

监守者有独立的 Brain、愤怒与周期黑暗机制，普通仇恨目标和伤害事件的主人保护不能完全接管这些机制，所以会出现“对主人攻击但不扣血，仍施加黑暗”的情况。

本版只对 LiPet 管理的监守者载体关闭原版自主感知与 Brain（保留移动物理），移动与攻击改由 LiPet 管理：

- 不再由宠物的原版 Brain 追打主人、施加范围黑暗或发动声波攻击。
- 保留 LiPet 主动索敌、主人指挥、属性伤害、WG 禁战规则、坐下与跟随。
- 跟随/战斗可通过已有可选 Pathfinder 接口取得路点，再以 Bukkit 速度与物理碰撞移动；未提供该接口的服务端使用原有速度兜底，不添加 NMS 依赖。不可达路径仍按跟随恢复或战斗卡住处理。
- 召唤、重新召唤、区块恢复和控制模式切换统一遵守监守者策略，不会被普通 AI 恢复逻辑重新开启 Brain。
- 不全局取消 DARKNESS，也不清除玩家已有药水效果；野生监守者、命令及其他插件产生的黑暗保留。升级前已生效的黑暗需等待原有效果自然结束。

这是监守者宠物的行为调整：原版声波/黑暗不再自动释放，对敌攻击使用 LiPet 的受控近战。其他宠物保留原有 AI 策略。

## 验证范围

- 默认 API 与 Paper 26.2 API 两套构建各通过 467 项测试，无失败、错误或跳过。
- 隔离 Paper 26.2 与 Folia 26.2 均通过：注入 150 愤怒值后运行超过两个黑暗触发周期，宠物不产生对主人的伤害尝试或黑暗效果；仍能主动追击敌怪并造成伤害、跟随远离的主人、坐下后重召恢复跟随。
- 两端均验证宠物旁边的野生监守者仍施加真实 DARKNESS 效果；没有全局屏蔽药水效果。
- 使用模拟玩家和自动化探针，不代表真人客户端动作、贴图或客户 Shiroha 特定组合验收。

## 更新

正常停止 Minecraft 服务端后替换 Jar，确保 plugins 及 update 中不重复放置旧 LiPet Jar；保留原有配置和数据库，正常启动并确认 `Enabling LiPet v0.29.5-SNAPSHOT`。已有监守者宠物建议先召回再重新召唤。不要用 PlugManX 或 `/reload` 替换 Jar，也不需要关闭电脑。

0.29.4 的 WG `lipet-spawn` / `lipet-attack` 与 MM 生成前置要求保持不变。
