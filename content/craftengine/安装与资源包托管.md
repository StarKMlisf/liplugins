# 安装、更新与资源包托管

运行要求、首次安装、资源包分发、版本更新和上线前检查。

## 运行要求

按 CraftEngine 官方 26.8 文档：

- Java 21 或更高版本；
- Minecraft 1.20 或更高版本；
- Paper、Folia 或官方兼容列表中的服务端分支；
- 玩家能够访问你配置的资源包下载地址。

下载 Community 或 Premium 版本时，只使用 [官方发布页](https://github.com/Xiao-MoMi/craft-engine/releases) 与官方列出的销售渠道。Community 和 Premium 的支持范围、专属功能及服务不同，教程示例不代表所有功能在两个版本中完全一致。

## 首次安装

1. 停止服务器。
2. 把 CraftEngine Jar 放入 `plugins/`。
3. 启动服务器并等待首次初始化完成。
4. 检查控制台中最早出现的 CraftEngine 错误，而不是只看最后一行。
5. 进入游戏执行 `/ce`；默认会打开物品浏览器。
6. 执行 `/ce reload all`，验证资源包生成、上传与发送链路。

首次启动后主要目录如下：

```text
plugins/CraftEngine/
├─ generated/       # 合并和生成后的产物
├─ libs/            # 运行时库
├─ resources/       # 服主安装或制作的内容包
├─ translations/    # 翻译文件
├─ commands.yml     # 命令、权限和路径
└─ config.yml       # 主配置
```

## 资源包为什么必须能下载

服务端知道物品逻辑，但贴图、模型、字体和声音需要通过资源包发送给客户端。若玩家拒绝资源包、下载地址不可访问或资源包生成失败，常见表现是：

- 物品显示为原版底材；
- 模型变成紫黑方块；
- 字体、图片或 GUI 图标缺失；
- 服务端功能正常，但玩家看到的外观不正常。

默认配置可使用 CraftEngine 自带的 `self` 托管。若网络环境不允许玩家访问服务器提供的 HTTP 地址，可按官方文档改用对象存储、外部直链、OpenList 等后端。

更改托管方式后执行：

```text
/ce reload all
```

只执行 `/ce reload config` 不会重新构建并发布资源包。

## 安全配置托管凭据

对象存储可能需要访问密钥。官方建议优先通过环境变量提供密钥，不要把真实密钥直接写进会分享、上传或提交 Git 的配置文件。

发布前检查：

- 下载 URL 可由公网或玩家所在网络访问；
- HTTPS 证书有效；
- 返回的是 ZIP 内容而不是登录页或 HTML 错误页；
- 文件哈希与服务器当前生成结果一致；
- 玩家接受资源包后没有紫黑贴图。

## 更新版本

1. 停服并备份整个 `plugins/CraftEngine/`，尤其是 `resources/`、`config.yml`、`commands.yml` 与世界数据。
2. 阅读目标版本发布说明，确认 Minecraft、Java 和配置变更。
3. 在测试服替换 Jar，完整启动一次。
4. 检查配置迁移和控制台警告。
5. 执行 `/ce reload all` 并重新连接客户端。
6. 测试代表性的物品、方块、家具、配方和资源包下载。
7. 验证完成后再更新正式服。

不要在服务器运行时覆盖 Jar，也不要使用通用热卸载插件替代完整重启。命令注册、底层方块状态和部分资源生命周期需要完整启动流程。

## 最小验收清单

```text
[ ] CraftEngine 已启用，没有启动失败
[ ] /ce 能打开物品浏览器
[ ] /ce resource list 能看到资源包
[ ] /ce reload all 成功完成
[ ] 玩家收到并接受资源包
[ ] 测试物品的名称与贴图正确
[ ] 测试方块可放置、破坏并正确掉落
[ ] 服务器能安全关闭并再次启动
```

官方参考：[Installation & Hosting](https://xiao-momi.github.io/craft-engine-wiki/getting_start/installation/)。
