# 资源目录、命名空间与热重载

创建资源包、理解 configuration/resourcepack、规范 ID 并选择正确重载范围。

## 创建第一个内容包

进入游戏执行：

```text
/ce resource create tutorial
```

CraftEngine 会在 `plugins/CraftEngine/resources/` 下创建 `tutorial`。它同时作为示例包名和默认命名空间，因此后续 ID 使用 `tutorial:ruby`、`tutorial:topaz_block`。

```text
plugins/CraftEngine/resources/tutorial/
├─ configuration/       # 物品、方块、家具、配方等 YAML
├─ resourcepack/        # 原版资源包结构
│  └─ assets/
│     └─ tutorial/
│        ├─ models/
│        └─ textures/
└─ pack.yml             # 名称、命名空间、作者、版本与启用状态
```

不建议手工猜测 `pack.yml` 的完整字段。先由 `/ce resource create` 生成，再按当前版本官方配置参考修改。

## 命名空间与 ID

完整 ID 的格式是：

```text
namespace:path
```

示例：

```text
tutorial:ruby
tutorial:weapons/topaz_sword
minecraft:diamond
```

建议：

- 命名空间和路径全部使用小写；
- 只使用小写字母、数字、`_`、`-`、`.` 和路径分隔 `/`；
- 发布后不要随意更改已发放内容的 ID；
- 不同资源包使用不同命名空间，避免路径覆盖；
- 插件配置和 API 中始终保存完整 ID，不只保存 `ruby`。

以 `.` 开头的资源目录会被 CraftEngine 忽略，可用于临时停用包，但正式管理更推荐使用 `/ce resource disable <包名>`。

## configuration 可以拆分

CraftEngine 会递归读取 `configuration/` 下的 YAML/JSON。可以按类型拆分：

```text
configuration/
├─ items.yml
├─ blocks.yml
├─ furniture.yml
└─ recipes/
   ├─ materials.yml
   └─ weapons.yml
```

也可以按主题拆分。关键是避免同一个完整 ID 在多个文件重复定义，并在团队内保持一致目录规则。

## resourcepack 使用原版路径

`resourcepack/` 是完整的 Minecraft 资源包根目录。例如：

```text
resourcepack/assets/tutorial/textures/item/ruby.png
resourcepack/assets/tutorial/models/item/ruby_sword.json
resourcepack/assets/tutorial/textures/block/topaz_block.png
```

模型 JSON 中的 `tutorial:item/ruby` 会解析到：

```text
assets/tutorial/textures/item/ruby.png
```

不要在模型里写 `C:\Users\...`、磁盘绝对路径或错误命名空间。

## 选择正确的重载

| 修改内容 | 命令 |
| --- | --- |
| 物品、方块、家具等 YAML | `/ce reload config` |
| 配方 | `/ce reload recipe` |
| 只重新生成资源包 | `/ce reload pack` |
| 贴图、模型、字体、声音或不确定范围 | `/ce reload all` |

`/ce reload` 不带参数时默认是 `config`。修改 PNG 或模型后只执行 `config`，客户端不会得到新资源包。

`commands.yml` 的命令路径、启用状态和权限注册改动需要完整重启，不能依赖 `/ce reload all`。

## 发布前目录检查

- 没有 Tab 缩进；
- 没有大写命名空间或文件名；
- 每个模型引用的贴图都真实存在；
- 同一路径没有被多个包意外覆盖；
- `/ce resource list` 显示目标包已启用；
- `/ce resource search <类型> <ID>` 能定位到预期配置文件。
