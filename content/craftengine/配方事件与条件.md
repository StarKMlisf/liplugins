# 配方、事件、函数与条件

有序和无序配方、标签、交互事件、执行函数与条件边界。

## 有序合成配方

```yaml
recipes:
  tutorial:topaz_shovel:
    type: shaped
    pattern:
      - "A"
      - "B"
      - "B"
    ingredients:
      A: tutorial:topaz
      B: minecraft:stick
    result:
      id: tutorial:topaz_shovel
      count: 1
```

修改配方后执行：

```text
/ce reload recipe
```

若运行了原版 `/minecraft:reload`、数据包重载或其他插件重载数据包，应再次重载 CE 配方。

## 无序配方与标签

```yaml
recipes:
  tutorial:topaz_dust:
    type: shapeless
    ingredients:
      - tutorial:topaz
      - "#minecraft:coals"
    result:
      id: tutorial:topaz_dust
      count: 2
```

前缀 `#` 表示标签。标签比逐个列出木板、矿石等同类物品更容易维护。物品自身也可以在 `settings.tags` 中加入 CE 或原版标签。

## 配方类型

官方当前支持的常见类型包括：

- `shaped`、`shapeless`；
- `shaped_transform`、`shapeless_transform`；
- `smelting`、`blasting`、`smoking`、`campfire_cooking`；
- `stonecutting`；
- `smithing_transform`、`smithing_trim`；
- `brewing`。

升级装备时优先了解 transform 配方及组件保留规则，避免耐久、附魔或自定义数据在合成后丢失。

## 物品事件

物品可根据交互触发函数：

```yaml
items:
  tutorial:signal_crystal:
    material: amethyst_shard
    data:
      item_name: "<!i><aqua>信号水晶"
    events:
      - on: right_click
        functions:
          - type: command
            command: "say signal crystal used"
```

常见物品触发器有 `break`、`right_click`、`left_click`、`consume`、`pick_up` 和 `attack`。方块与家具拥有各自触发器，并且事件必须放在正确对象层级：家具交互事件应位于 `furniture`，不能错误放在用于放置它的 item 层。

## 函数条件

函数可以附带条件，例如权限：

```yaml
functions:
  - type: command
    command: "say allowed"
    conditions:
      - type: permission
        permission: tutorial.signal.use
```

不同版本和 Community/Premium 版本可用的函数、条件、脚本与配方增强能力可能不同。正式配置前应查阅当前官方页面，不要因为某段示例能解析就认定所在版本一定提供该功能。

## 设计建议

- ID 保持稳定，显示名可以本地化；
- 配方结果使用完整 `namespace:id`；
- 命令函数不要拼接不可信玩家输入；
- 高成本函数增加冷却或条件；
- 先测试失败条件，再测试成功路径；
- 涉及经济、权限或物品扣除时验证失败是否会错误消耗材料。
