# 模型、贴图与 BlockBench

资源路径、texture 简写、自动生成、外部模型和紫黑贴图检查。

## 文件放在哪里

```text
resourcepack/assets/tutorial/
├─ textures/
│  ├─ item/
│  │  └─ toxic_sword.png
│  └─ block/
│     └─ topaz_block.png
└─ models/
   └─ item/
      └─ toxic_sword.json
```

物品和方块贴图应放在 `textures/item/` 或 `textures/block/`。文件名和引用路径全部使用小写。常规贴图建议使用 16×16、32×32、64×64 等 2 的幂尺寸。

## 方法一：一行 texture

只有一张贴图时最简单：

```yaml
items:
  tutorial:toxic_sword:
    material: golden_sword
    texture: tutorial:item/toxic_sword
    data:
      item_name: "<!i><gradient:#62E6A7:#27A66B>淬毒之刃"
```

CraftEngine 会根据底材选择常见父模型并生成需要的模型文件。修改后执行 `/ce reload all`。

## 方法二：generation 控制生成

需要指定父模型、多层贴图或显示变换时：

```yaml
items:
  tutorial:toxic_sword:
    material: golden_sword
    model:
      path: tutorial:item/toxic_sword
      generation:
        parent: minecraft:item/handheld
        textures:
          layer0: tutorial:item/toxic_sword
```

常见父模型：

| 父模型 | 用途 | 常用贴图变量 |
| --- | --- | --- |
| `minecraft:item/handheld` | 剑、工具 | `layer0` |
| `minecraft:item/generated` | 食物、材料、平面图标 | `layer0` |
| `minecraft:block/cube_all` | 六面相同方块 | `all` |

贴图变量由父模型决定，不能随意命名。

## 方法三：使用外部模型 JSON

从 BlockBench 导出的模型放在 `models/item/`，配置直接引用：

```yaml
items:
  tutorial:toxic_sword:
    material: golden_sword
    model: tutorial:item/toxic_sword
```

模型内部建议使用命名空间路径：

```json
{
  "textures": {
    "0": "tutorial:item/toxic_sword",
    "particle": "tutorial:item/toxic_sword"
  }
}
```

`tutorial:item/toxic_sword` 会解析到 `assets/tutorial/textures/item/toxic_sword.png`。

## BlockBench 导入检查

1. 把模型 JSON 放入目标命名空间的 `models/`。
2. 把 PNG 放入 `textures/item/` 或 `textures/block/`。
3. 搜索模型内作者原命名空间，例如 `fantasy_pack:`。
4. 只有在文件也同步移动后，才能批量替换为自己的命名空间。
5. 检查 `display` 变换，分别查看手持、GUI、地面和头部姿态。
6. 执行 `/ce reload all`，重新接收资源包后实机检查。

## 紫黑贴图排查

| 表现 | 常见原因 | 处理 |
| --- | --- | --- |
| 整个物品是紫黑 | 模型或贴图路径不存在 | 逐字符核对命名空间、目录和扩展名 |
| GUI 正常、手持异常 | `display` 变换错误 | 在 BlockBench 检查对应显示槽位 |
| 修改后完全没变化 | 只重载了 config | 执行 `/ce reload all` 并重新发送资源包 |
| 只有部分玩家错误 | 客户端仍使用旧包 | 检查新包 URL/哈希并重新连接 |
| 模型引用磁盘路径 | BlockBench 保存了绝对路径 | 改为 `namespace:item/name` |
