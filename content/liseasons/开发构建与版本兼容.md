# 开发构建与版本兼容

## 项目基线

- Maven 项目；
- Java release 21；
- Paper API 最低编译基线 1.21.1；
- PacketEvents 2.13.0 由 `lib/` 本地提供；
- PlaceholderAPI 2.11.6 为 `provided`；
- JUnit Jupiter 5.10.3 用于测试。

## 标准构建

PowerShell：

```powershell
$env:JAVA_HOME = 'C:\Program Files\Java\jdk-21'
mvn clean package
```

默认产物：

```text
target/LISeasons-1.0.70.jar
```

项目另有 `obfuscate` Maven profile。对外 API、主类、PAPI 和集成入口有 ProGuard 保留规则；混淆构建发布前仍需真实服务器加载验证。

## 依赖打包规则

成品 Jar 只包含 LISeasons 自身业务类和资源，不应打入：

- Bukkit/Paper API；
- CraftBukkit 或服务端 NMS 类；
- PacketEvents；
- PlaceholderAPI；
- ProtocolLib。

Residence / CMILib 仅供可选领地插件和隔离集成测试使用，不是 LISeasons 的编译依赖，不打入成品。

PacketEvents 是运行时服务器插件依赖，不是 shaded Java 库；ProtocolLib 已不再使用。

## 客户端染色结构

1.0.67 不再维护按服务端版本区分的 NMS 群系修改器。`SeasonBiomeColorService` 负责季节目标、玩家周围区块缓存和共享预算，`PacketEventsBiomePacketSender` 只负责按玩家客户端协议生成 `CHUNK_BIOMES`。

新加载区块会先收到服务端正常的 `CHUNK_DATA`，随后追加当前季节的客户端群系包。换季时，服务按在线玩家共享预算刷新已有视距。整个流程不调用 `setBiome`、`refreshChunk`、CraftBukkit 或 NMS，也不会给区块标记待保存。

兼容范围需要同时满足：

1. Paper API 能在 1.21.1 基线上编译；
2. PacketEvents 2.13.0 或更高兼容版本正常初始化；
3. PacketEvents 能识别对应客户端的群系注册表并编码 `CHUNK_BIOMES`；
4. Paper 与 Folia 调度路径遵守各自线程边界；
5. 客户端进入世界、移动加载新区块和换季时都能看到颜色变化。

因为已经没有服务端内部方法链接，普通补丁版本升级不再需要重写 NMS 适配器；但协议、PacketEvents 或服务端区块发包流程变化后仍需重新做真实启动与客户端观察。
