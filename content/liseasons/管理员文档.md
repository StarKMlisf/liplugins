# 管理员文档 · 总览

面向服主与运维人员的 LISeasons 部署、配置、备份、性能和排障入口。

## 管理职责

管理员不需要手动维持每一天的季节，但需要为自然系统建立稳定、可解释的运行边界：

- 选择受支持的服务端核心、Java 与 ProtocolLib 版本；
- 决定哪些世界启用季节以及使用哪种日历模式；
- 在启用 NMS 群系改写前完成正式世界备份；
- 调整作物、天气、冰雪、体温、事件和节日强度；
- 为高在线服务器设置合理的区块半径和全局预算；
- 在升级前保留 `plugins/LISeasons/` 和世界数据；
- 用普通玩家账号验证菜单、权限、占位符和事件观感。

## 一次完整的部署顺序

1. 确认服务端核心本身可以使用 Java 21 或服务端要求的更高版本稳定启动；
2. 安装与当前服务端匹配的 ProtocolLib；
3. 将 LISeasons JAR 放入 `plugins/`，启动一次生成配置；
4. 检查日志中 LISeasons、ProtocolLib 与 NMS 适配器是否正常启用；
5. 停服备份世界和 `plugins/LISeasons/`；
6. 在 `config.yml -> worlds` 配置启用世界和日历模式；
7. 按需调整 `temperature.yml`、`season-color.yml`、`season-events.yml` 与 GUI 文件；
8. 完整重启或在确认允许重载的场景执行 `/seasons reload`；
9. 使用普通账号进入测试世界，检查四季信息、菜单、体温、颜色和事件；
10. 观察控制台和性能采样，确认没有异步线程错误或预算堆积后再开放正式世界。

## 配置文件地图

| 文件 | 管理内容 | 运维说明 |
| --- | --- | --- |
| `config.yml` | 日历、世界、季节规则、天气、冰雪、生物和集成 | 主要入口；重载后验证世界任务 |
| `messages.yml` | 命令、通知、HUD、GUI 文本和名称映射 | 可自定义 MiniMessage 文本 |
| `temperature.yml` | 体温、潮湿、装备、物品、热源与效果 | 修改后用普通玩家现场验证 |
| `season-color.yml` | NMS 群系染色、半径、预算和目标群系 | 会影响世界区块数据，先备份 |
| `season-events.yml` | 16 个事件、流星轨迹和陨石奖励 | 视觉效果需要客户端录像验收 |
| `festivals.yml` | 现实日期节日 | 使用服务器现实日期 |
| `gui.yml`、`gui/*.yml` | 日历菜单布局、图标、文本和动作 | 缺失默认节点会自动补齐 |
| `calendar-state.yml` | 服内日历运行状态 | 插件维护，运行中不要手改 |

## 生产环境最小安全基线

```yaml
# config.yml
worlds:
  - world

# season-color.yml
biome-spoof:
  radius-chunks: 6
  budget-chunks-per-tick: 4
  nms:
    enable: true
```

上面的数值只是偏保守的起点，不是适合所有服务器的最终配置。正式启用前必须核对当前配置文件的真实层级，并根据在线人数、视距、模拟距离和其他区块插件做压测。

## 管理员常见误区

- 只换 JAR 后执行重载，未完整重启 ProtocolLib 与 NMS 模块；
- 用 OP 账号验证普通玩家权限，误以为所有玩家都能使用；
- 同时提高染色半径、每轮预算和刷新频率，造成突发区块压力；
- 把群系染色当作纯客户端效果，未备份就应用到正式世界；
- 只看报错最后一行，没有保留最早出现的线程和调用来源。
