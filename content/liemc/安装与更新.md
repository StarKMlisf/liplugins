# LIEMC 安装与更新

当前版本：`0.1.0+build.107`

## 运行环境

- Paper / Luminol 26.1.2
- Java 25
- SQLite 或 MySQL
- Vault、PlayerPoints、PlaceholderAPI 按需安装

## 首次安装

1. 关闭服务器。
2. 将 LIEMC JAR 放入 `plugins/`。
3. 启动服务器并等待 `plugins/LIEMC/config.yml`、`gui.yml` 和 `lang.yml` 生成。
4. 根据单服或群组服选择存储方式。
5. 检查经济来源和默认物品价格。
6. 完整重启，执行 `/emc` 和 `/emc convert` 验证菜单。

运行库由插件声明加载，不需要把数据库驱动手动塞进插件 JAR。

## 单服与群组服选择

| 场景 | 推荐存储 |
| --- | --- |
| 单个生存服、测试服 | SQLite |
| 多子服共享余额与解锁 | MySQL |

群组服还需要确保所有子服使用相同数据库、商品 ID 和兼容配置。详见[存储与跨服](./存储与跨服.md)。

## 更新步骤

1. 停服并备份 `plugins/LIEMC/` 与数据库。
2. 替换插件 JAR，不删除现有配置。
3. 启动服务器，观察配置补全和数据库迁移日志。
4. 执行 `/emc reload` 后重新验证菜单、出售和兑换。
5. 多子服环境逐台更新，避免长期混跑不同版本。

升级到 build.98 后，旧菜单会迁移到独立 `gui.yml`，缺失节点与默认注释会安全补齐，不覆盖已有自定义值。界面修改方法见[自定义 GUI 完整教程](./自定义GUI教程.md)。

## 从 build.105 升级到 build.106

build.107 包含下述数据库及 Lore 修复；从更早版本也可直接升级到 build.107。

build.105 在部分 MySQL 8.0 环境初始化 `description_lore` 字段时，会因 `TEXT` 字段使用普通字符串默认值而启用失败。build.106 移除了 MySQL `TEXT` 默认值，并改为“新增可空字段、回填空值、再收紧为非空”的可恢复迁移流程。

1. 停止所有连接同一 LIEMC 数据库的子服，并备份数据库与 `plugins/LIEMC/`。
2. 将各子服的 build.105 JAR 替换为 `LIEMC-0.1.0+build.106.jar`，不要删除现有表、字段或配置。
3. 先启动一台子服，等待数据库迁移和插件启用完成；即使 build.105 已留下半迁移字段，build.106 也会检查当前列状态并继续补齐。
4. 确认控制台不再出现 `description_lore can't have a default value`，再依次启动其余子服。
5. 执行 `/emc reload`，重新打开获取、搜索和收藏菜单，确认空白 Lore 分隔行与价格信息正常。

此次升级不要求手动执行 `ALTER TABLE`，也不应通过删除 `liemc_shop_items` 表来规避错误。完整变更见[build.106 更新说明](./更新日志-build106.md)。

## 不建议的操作

升级 build.107 后会补齐 `sell-pricing` 和新语言节点，保留原配置、权限规则和自定义文案。出售倍率默认关闭，必须自行设置并执行 `/emc reload` 才启用。旧 GUI 自定义 Lore 不会被覆盖，可按[出售权限折扣与倍率](./出售权限倍率.md)添加新变量。

- 不使用第三方热加载插件替换完整重启。
- 不在未备份时批量删除商品或切换数据库。
- 不把测试服和正式服指向同一数据库后执行破坏性测试。
