# 配置与故障排查

配置位于 plugins/LiWeaponReset/config.yml。修改后执行 `/wr reload`，自动开关立即按新设置检查，旧预览取消。消息集中于 messages.yml，支持 MiniMessage、RGB 和渐变；保留消息中的占位符。

## 默认配置

```yaml
# 预览有效期，单位秒，整数 5～600。
preview-seconds: 60
# true/false：所有在线玩家主手每 20 tick 自动检测一次。
# 始终要求米饭标记；将全部攻击伤害和攻速恢复为材质原版值。
# 自定义武器需要人工核对时请设 false。
auto-restore-enabled: true
# true/false：手动操作是否要求米饭标记，不影响自动检测限制。
require-rice-marker: true
# true/false：回归时删除米饭等级标记。
remove-level-marker: true
# true/false：删除米饭默认彩色 [+等级] 名称尾缀，不删除其他名称内容。
remove-default-name-suffix: true
# 合法 Java 正则，匹配 Bukkit 材质枚举名称，不建议扩展到材料或方块。
weapon-pattern: ".*_(SWORD|AXE|SPEAR)|TRIDENT|MACE|BOW|CROSSBOW"
```

即使关闭 remove-level-marker，回归后的事务标记也会阻止重复自动处理。messages.yml 可调整 auto-restored 成功提示、auto-error-log 错误日志和其他指令反馈。

## 拿在手里没有恢复

1. 确认插件启动成功、自动开关为 true，并执行过重载。
2. 确认 PlayerIntensify 已移除，而不是仍处于启用状态。
3. 必须拿在主手、数量为 1，且材质符合正则。
4. 用 `/wr inspect` 查看米饭标记；只有 Lore 文本、其他版本标签或自定义 NBT 并不满足自动条件。
5. 已处理或 undo 撤销后的武器会被跳过；需要再次操作使用手动预览确认。
6. 检查备份目录写入权限和磁盘空间；失败后会等待 30 秒重试。不要靠删除事务标记掩盖备份故障。

## 属性看起来仍然很高

本插件只回归物品攻击修饰符，不更改附魔、玩家基础值、CE 或其他插件动态加成，也不删除显示在 Lore 的旧文字。请先通过 inspect 区分真实修饰符与显示文本，再排查对应来源。

## 无法撤销

要求原玩家 UUID、回归后完整物品、存在且未使用的备份记录。磨损、改名、附魔等都会造成不匹配；此时不要重复复制装备，可由管理员核对原始备份。详见[指令与备份撤销](指令与撤销.md)。

## 自检

在测试服执行 `/wr validate`，测试文件仅写入 validation-backups，不接触在线玩家背包。默认配置下本版通过 51 项检查；自定义配置会影响测试条件，关闭自动功能时测试分支与数量不同。首次运行库下载失败时应检查网络和启动日志，不应安装米饭插件作为前置。
