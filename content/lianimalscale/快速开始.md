# LiAnimalScale

LiAnimalScale 是面向 Paper、Folia 与 Luminol `1.21.11+` 的动物实体缩放插件，
并兼容较新的 `26.1.2`。它直接修改 Bukkit
`Attribute.SCALE`，因此动物的模型、碰撞箱和交互范围会由服务端按原生规则处理，
不生成盔甲架或展示实体，也不使用 NMS。

## 默认行为

- 插件启动后，把当前已加载的全部动物放大为 3 倍。
- 之后新生成的动物也会自动放大为 3 倍。
- 倍率、实体名单、名单模式和启动扫描均可在 `config.yml` 修改。
- 修改过的实体属性由 Minecraft 随实体数据保存，区块卸载后不会自动丢失。
- Paper、Folia 与 Luminol 共用区域安全调度层，实体操作始终在实体所属区域执行。
- `/animalscale reload` 使用异步文件读取，支持无重启热重载配置。

## 指令

| 指令 | 说明 | 权限 |
| --- | --- | --- |
| `/animalscale set [倍率]` | 对准动物并设置倍率，省略时使用默认倍率 | `lianimalscale.set` |
| `/animalscale reset` | 恢复所看动物的原始大小 | `lianimalscale.reset` |
| `/animalscale get` | 查询所看动物的倍率 | `lianimalscale.get` |
| `/animalscale applyloaded [倍率]` | 批量缩放当前已加载动物 | `lianimalscale.applyloaded` |
| `/animalscale reload` | 重载配置与消息文件 | `lianimalscale.reload` |

主指令别名：`/as`、`/animalgiant`、`/动物缩放`。所有指令均带 Tab 补全。

## 安装

1. `1.21.11` 服务端使用 Java 21；`26.1+` 服务端使用 Java 25。
2. 将 `LiAnimalScale-1.1.0.jar` 放入服务器 `plugins/`。
3. 启动服务器。服务端会按 `plugin.yml` 自动加载 MiniMessage 运行库。
4. 根据需要编辑 `plugins/LiAnimalScale/config.yml` 和 `messages.yml`。

## Paper / Folia / Luminol 与热加载

- `plugin.yml` 已声明 `folia-supported: true`。
- 玩家指令在玩家区域获取目标，属性修改通过 EntityScheduler 回到目标实体区域。
- 批量处理先在全局区域收集快照，再逐个派发到实体区域，不跨区域直接改实体。
- 配置使用不可变快照，可供多个 Folia/Luminol 区域线程并发读取。
- `/as reload` 会在异步调度器读取文件，是日常修改配置的推荐热重载方式。
- 插件停用时会注销监听器并取消全部已跟踪任务，可安全完成规范的
  `卸载旧实例 → 使用新类加载器加载新实例 → onEnable` 热加载生命周期。

Paper `1.21.11` 与 `26.1.2` 的 `bukkit:reload confirm` 均通过实测。
Folia/Luminol 不支持服务器级 `bukkit:reload`，请勿执行它；配置修改统一使用
`/as reload`。

Folia `1.21.11` 与 `26.1.2` 已实测通过单插件热加载：旧实例停用后，由新类加载器
重新加载 Jar，新实例仍能自动缩放动物并重载配置。Luminol `1.21.11` 官方 API
独立兼容构建也已通过。热插拔工具必须真正卸载旧实例并创建新类加载器，不能把已经
关闭类加载器的旧实例直接再次启用。更新 Jar 时仍建议正常重启服务器。

## 构建

```powershell
mvn clean package
mvn -Pluminol-compat clean package
```

第一条使用 Paper 1.21.11 API 构建，第二条使用 Luminol 1.21.11 官方 API 执行
独立兼容构建。API、Adventure 和 MiniMessage 均不会被打进成品 Jar。
