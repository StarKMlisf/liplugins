# 故障排查

目标：你可以通过这张清单，快速把“看起来像没问题”的情况从“真的没问题”里分离出来。

## 0. 先定性：是命令问题还是运行时问题？

- 玩家报错“命令无效” -> 命令层问题  
- 进副本后无反应 -> 触发链/世界实例层问题  
- 服务器日志出现等待/卡顿 -> 调度层或异步回收问题  

## 1. 基础排查（每次故障都先做）

1. 启动日志  
   - 看到插件加载成功提示  
   - 配置版本/初始化提示可读  
2. 命令验证  
   - `/lidungeon help` 可执行  
   - 是否能进入编辑：`/lidungeon edit <dungeonId>`  
3. 副本入口验证  
   - `/lidungeon join <dungeonId>`  
   - 有无实例分配日志  
4. 触发器验证  
   - 关键触发是否有匹配记录  

## 2. 常见问题树

### A. 命令不可用
- 权限不足：确认指令节点和执行人权限  
- 旧入口残留：外部指引未统一为 `/lidungeon`  
- 插件未加载：检查启动日志和文件加载路径

### B. 编辑卡顿或超时
- 编辑时高并发调用触发过多；
- 配置链过长、触发闭环；
- 世界池状态不稳定；
- 处理建议：先只保留最小触发链测试，逐步恢复；

### C. 进副本成功但没有触发
- 入场事件触发后条件不满足；
- 阶段配置与实际副本阶段不一致；
- 世界/实例 ID 错配；
- 处理建议：导出副本配置逐段对照（事件->条件->动作）。

### D. 奖励不发放
- 奖励动作未绑定触发；
- 触发条件仅满足但动作因依赖异常终止；
- 外部经济/占位符插件未就绪；
- 处理建议：先在不涉外部依赖环境下验证“纯奖励文本提示”，再打开联动功能。

### E. 进入后卡死/日志出现长等待
- 副本实例状态未回收；
- 触发链进入自旋/重复等待；
- 处理建议：记录触发链与时间戳，逐步注释掉动作后重测。

## 3. 日志看法：三行一读

- 第一行：谁触发了哪个副本/阶段；  
- 第二行：为什么被条件拦截（若有）；  
- 第三行：动作是否执行成功。  

缺失其中任意一行，通常说明问题在上游配置而非下游动作本身。

## 4. 恢复与回滚

### 立即恢复
- 回退到上一个可用副本配置；
- 重载配置；
- 以测试副本先跑最小流程再放量；

### 持续故障
- 暂停新增副本编辑；
- 保留现有稳定副本供玩家运行；
- 分阶段恢复触发链（先事件，后条件，最后动作）。

## 5. 与官方日志中的关键提示对应

- “游戏规则配置版本过旧”：通常表示补齐更新，不是默认崩溃，先确认加载是否继续；
- 启动成功后仍无事件：先排查触发条件是否可达；
- 一直卡在编辑：优先确认编辑链是否包含非预期等待步骤。

## 6. 验收模板（建议每次故障修完后打勾）

- [ ] `/lidungeon help` 可正常返回  
- [ ] `/lidungeon edit` 可进入编辑状态  
- [ ] `/lidungeon join` 可进入至少一个副本  
- [ ] 一条触发链可正常执行  
- [ ] 奖励或阶段回退可见  
- [ ] 副本实例可正常回收
