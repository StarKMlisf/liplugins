# 功能、奖励与流程编排

“功能”是触发器通过条件后执行的动作。基础环境加载 38 个功能；MythicMobs 会增加 Mythic 技能/信号并替换战利品表实现，Citizens 会再增加 NPC 生成器，最多可见 41 个。

## 基础功能清单

### 地牢与玩家流程

| 中文名 | 内部类型 | 用途 |
| --- | --- | --- |
| 开始地牢 | `FunctionStartDungeon` | 从大厅正式开始 |
| 完成地牢 | `FunctionFinishDungeon` | 登记完成、处理冷却，可选择离开 |
| 离开地牢 | `FunctionLeaveDungeon` | 立即移出目标，不登记完成 |
| 重生检查点 | `FunctionCheckpoint` | 设置死亡/重连检查点，可作为存档点 |
| 生命数编辑器 | `FunctionLives` | 设置或增减玩家生命 |
| 玩家复活器 | `FunctionRevivePlayer` | 复活仍在旁观的死亡玩家 |
| 传送器 | `FunctionTeleport` | 传送目标玩家到配置位置 |
| 地牢难度 | `FunctionSetDifficulty` | 修改 LiDungeon 难度 ID |
| 地牢状态 | `FunctionSetStatus` | 设置自定义状态字符串 |

### 提示与表现

| 中文名 | 内部类型 | 用途 |
| --- | --- | --- |
| 消息发送器 | `FunctionMessage` | 聊天栏或动作栏消息 |
| 标题 | `FunctionTitle` | 标题/副标题、淡入、停留、淡出 |
| 声音播放器 | `FunctionPlaySound` | 声音、类别、音量、音调、位置 |
| Boss 血条 | `FunctionBossBar` | 标题、颜色、样式、固定或变量/PAPI 进度 |
| 全息文本 | `FunctionHologram` | 在位置显示/隐藏文本，设置可视距离 |

### 世界、方块与门

| 中文名 | 内部类型 | 用途 |
| --- | --- | --- |
| 允许放置/破坏方块 | `FunctionAllowBlock` | 为位置加入放置、破坏、桶操作的白/黑名单 |
| 方块编辑器 | `FunctionBlockEditor` | 放置或移除指定方块并设置朝向 |
| 区块加载器 | `FunctionChunkLoad` | 强制加载半径内区块；再次触发释放 |
| 门控制器 | `FunctionDoorControl` | 锁定/解锁位置门，可隐藏钥匙名 |
| 房间门控制器 | `FunctionRoomDoor` | 程序化房间按门名开关 |
| 放置红石块 | `FunctionRedstoneBlock` | 按延迟、间隔和次数放置红石块 |
| 移动方块 | `FunctionMovingBlock` | 把方块转为移动实体并移动到终点 |
| 移动方块集群 | `FunctionMovingCluster` | 选择区域并整体移动 |

移动方块的实体承载受网络延迟影响；启用 `Experimental.MovingBlocksMoveEntities` 后仍要实机测试，向上移动时服务器需要 `allow-flight=true`。

### 物品、怪物与变量

| 中文名 | 内部类型 | 用途 |
| --- | --- | --- |
| 物品发放器 | `FunctionGiveItem` | 向目标发放或在位置掉落物品 |
| 钥匙发放器 | `FunctionGiveKey` | 发放可供钥匙触发器使用的钥匙，可控制是否带出 |
| 生物生成器 | `FunctionSpawnMythicMob` | 生成原版/支持的 Mythic 生物，配置数量、间隔、延迟、等级 |
| 地牢变量 | `FunctionInstanceVariable` | 修改当前实例共享变量 |
| 玩家变量 | `FunctionPlayerVariable` | 修改每名玩家变量，可跨场次保留 |
| 指令执行器 | `FunctionCommand` | 以玩家、临时 OP 玩家或控制台执行，可逐玩家运行 |
| 信号发送器 | `FunctionRemoteTrigger` | 向同名远程触发器发信号 |

控制台指令不要假设玩家变量一定存在；逐玩家执行时确认目标人数，避免一条高开销命令被成倍执行。

### 逻辑编排功能

| 中文名 | 内部类型 | 用途 |
| --- | --- | --- |
| 多功能组合 | `FunctionMulti` | 同时运行一组功能 |
| 条件功能 | `FunctionConditional` | 条件通过执行 THEN，否则执行 ELSE |
| 延迟功能 | `FunctionDelayed` | 等待后运行一个子功能 |
| 随机功能选择器 | `FunctionRandom` | 从列表随机执行一个 |
| 功能重复器 | `FunctionRepeater` | 延迟后按间隔重复，限制最大次数 |
| 功能序列器 | `FunctionSequence` | 每次触发执行列表下一个，可循环 |

避免无限重复、重复器套重复器或在多个远程触发器间形成闭环。设计循环时必须有最大次数、状态条件或停止信号。

## 奖励功能

| 中文名 | 用途 |
| --- | --- |
| 奖励 | 配置物品、经验与领取冷却的奖励菜单 |
| 随机奖励 | 设置最少/最大奖励数，从配置池随机选择 |
| 战利品表奖励 | 从 LiDungeon 战利品表生成奖励；安装 MythicMobs 后使用支持 Mythic 掉落表的实现 |

创建战利品表：

```text
/lidungeon loot create boss_rewards
/lidungeon loot edit boss_rewards
```

奖励与“完成地牢”是两个独立动作。推荐流程：

```text
Boss 死亡 -> 战利品表奖励 -> 完成地牢
```

若 `GiveLootAfterCompletion: true`，奖励先进入待发列表，只有完成后发出。测试时同时验证背包已满、重复领取、冷却、断线和未完成离开。

## 可选功能

| 依赖 | 新增/替换功能 | 注意 |
| --- | --- | --- |
| MythicMobs | Mythic 技能、Mythic 信号、Mythic 战利品表 | 依赖必须先成功加载；跨区域目标可能受 Folia 线程边界限制并记录警告 |
| Citizens | NPC 生成器 | NPC ID 必须存在；复制实例后验证生命周期和清理 |

## 目标类型

功能可以面向触发玩家、全部玩家、队伍、位置或无目标。并非每个触发器都能提供所有目标：

- 红石触发没有明确玩家；
- 地牢开始适合面向实例全体；
- 玩家检测、聊天、交互适合面向触发玩家；
- 位置功能应确认使用模板坐标还是实例坐标。

功能“看起来配置正确但没有效果”时，先把同一触发器绑定一个简单消息功能。如果消息能执行，问题通常在目标类型、依赖或具体功能参数。

## 推荐编排原则

1. 一个节点负责一件事。
2. 用状态/变量表达阶段，不靠大量隐式延迟。
3. 关键阶段同时发一条管理员可识别消息或状态变化。
4. 奖励与完成分开测试。
5. 所有循环都有上限。
6. 所有离开路径都能回收实例。
