# 单地牢配置

每个地牢的配置位于 `plugins/LiDungeon/maps/<地牢ID>/config.yml`。新地牢从 `maps/default-config.yml` 复制默认值。除特别说明外，修改后使用 `/lidungeon reload <地牢>`，活动实例应先清空。

## General：基础生命周期

| 字段 | 说明 |
| --- | --- |
| `Version` | 配置迁移版本，不要手工降低 |
| `DungeonType` | `CLASSIC`、`PROCEDURAL`、`CONTINUOUS` |
| `ChunkGenerator` | 世界生成器；内置 `lidungeon:void`、`lidungeon:block.<BLOCKTYPE>` |
| `DisplayName` | 开始/完成时显示名称 |
| `ShowTitleOnStart` | 开始时是否显示标题 |
| `Lobby.Enabled` | 是否先进入大厅，等待“开始地牢”功能 |
| `ExitLocation` | `/lidungeon setexit <地牢>` 写入的出口 |
| `AlwaysUseExit` | 是否所有离开方式都使用出口 |
| `Gamemode` | 地牢内游戏模式 |
| `PlayerLives` | 可死亡次数；0 为无限 |
| `InstantRespawnPlayers` | 是否跳过原版死亡界面 |
| `DeadPlayersSpectate` | 耗尽生命后旁观还是离开 |
| `CloseDungeonWhenAllSpectating` | 全员旁观后是否关闭实例 |
| `KeepInventoryOnEnter` | 是否带入当前背包 |
| `KeepHealthOnEnter` / `KeepFoodOnEnter` | 是否保留进入前生命/饥饿 |
| `KeepPotionEffectsOnEnter` | 是否保留药水效果 |
| `KeepExpOnEnter` | 是否保留经验 |
| `KickOfflinePlayers` | 是否在断线后移出地牢 |
| `KickOfflinePlayersDelay` | 断线后等待秒数 |
| `ReturnToCheckpointOnRejoin` | 重连时回最近检查点 |
| `CombatLogPenalty` | 战斗中退出是否扣一条生命 |
| `CombatLogSeconds` | 受伤后判定战斗退出的秒数 |
| `MaxBackups` | 地牢历史备份保留数 |
| `MaxInstances` | 此地牢最大并发实例 |
| `TimeLimit` | 自动结束分钟数；0 关闭 |
| `CleanupDelay` | 无人后延迟清理 tick 数 |
| `MaxPlayers` | 持续型地牢的实例容量 |

## 队伍与准备的单地牢覆盖

可在地牢配置中取消注释并覆盖：

```yaml
LeaderOnlyQueue: true
ReadyCheckOnCommand: true
ReadyCheckInQueue: true
ReadyCheckTime: 45
StartWithoutUnreadyPlayers: false
ReadyCheckRequireLeader: true
IgnoreParties: false
```

省略字段时继承全局。`IgnoreParties: true` 会让已有队伍的玩家也单独进入，不做队伍队列、队长限制、队伍最小人数检查，也不把队员加入实例。

## 奖励发放与冷却

`GiveLootAfterCompletion: true` 会把奖励功能取得的物品先放入奖励列表，完成地牢后再发放。

`LootCooldown` 限制重复领取奖励：

- `Enabled`：是否启用；
- `PerReward`：每个奖励点独立，还是整个地牢共用；
- `CooldownType`：`TIMER`、`HOURLY`、`DAILY`、`WEEKLY`、`MONTHLY`；
- `CooldownTime`：TIMER 时为分钟，否则用于重置小时；
- `ResetDay`：每周/每月重置日。

`AccessCooldown` 限制再次进入，可分别在完成、离开、耗尽生命、开始时应用。多人地牢使用进入冷却要谨慎：任何一名队员冷却中都可能阻止整队。

## Requirements：进入要求

| 字段 | 说明 |
| --- | --- |
| `Permissions` | 所有必须权限 |
| `MinPartySize` / `MaxPartySize` | 队伍人数范围 |
| `MaxPartyDistance` | 队员与队长最大距离；0 关闭，跨世界视为超距 |
| `KickDistantMembers` | 超距队员是否同时移出队伍 |
| `DungeonsComplete` | 必须完成的地牢 ID 列表 |
| `PlayerLevel` | 最低等级；0 关闭 |
| `PlayerLevelType` | `VANILLA` 或 `MYTHICRPG` |
| `MythicRPGGroup` | MythicRPG 原型组 |
| `Cost` | Vault 费用；0 免费 |
| `LeaderOnlyCost` | 是否只扣队长 |
| `JoinSkill` | 可选 MythicMobs 技能，调用 `denyjoin` 拒绝进入 |
| `JoinDenyMessage` | JoinSkill 拒绝但未自行提示时的回退文本 |

## AccessKeys

- `Consume`：进入时消耗；
- `LeaderOnly`：是否只检查/消耗队长钥匙；
- `KeyItems`：序列化钥匙列表，推荐用 `addkey`/`removekey` 管理。

## Difficulty

`EnableDifficultyLevels` 开启难度，`EnableDifficultyMenu` 控制是否显示选择菜单。每个 `Levels.<ID>` 可配置图标、怪物生命/数量/伤害倍率、MythicMobs 额外等级和奖励加成。

`Overrides` 可按难度覆盖 `TimeLimit`、`PlayerLives`、`MaxPlayers`、`KeepInventoryOnEnter`、`InstantRespawnPlayers`。

`MobOverrides` 可按具体怪物 ID 设置绝对数量、数量倍率、生命、伤害和额外等级。绝对 `Count` 优先于倍率。

## Map

| 字段 | 说明 |
| --- | --- |
| `GiveOnJoin` | 进入时发地图 |
| `MaxRenderDepth` | 随高度差淡出的深度 |
| `DisplayFloors` | 是否显示楼层 |
| `FloorDepth` | 楼层高度间隔 |
| `ShowAllPlayers` | 是否显示其他玩家 |

## Rules：玩法保护

规则覆盖生物生成、方块放置/破坏、桶、末影珍珠、紫颂果、实体放置、丢弃、随机刻、植物、爆炸、PvP、死亡消息、外部传入、命令白名单、禁用物品、黑白名单方块、实体保护、交互类别和耐久损失。

重点顺序：

1. `AllowBreakBlocks` / `AllowPlaceBlocks` 是总开关；
2. 方块白名单允许例外；
3. 黑名单明确禁止；
4. `AllowBreakPlacedBlocks` 可允许玩家拆自己放置的方块，并会覆盖前述规则；
5. 自定义物品建议用命令写入 `CustomBannedItems`。

改规则后必须用普通玩家账号测试放置、破坏、容器、合成、拾取、爆炸和命令，不要只用 OP 测试。
