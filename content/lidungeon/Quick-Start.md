# 五分钟快速开始（运营可执行版）

## 0. 先做 3 件事（避免踩坑）

1. 停服并备份：`plugins/LiDungeon/`（`config`、`dungeons`、`data`）
2. 确认主命令统一：只保留 `/lidungeon` 作为对外主入口
3. 进入服务器后执行一次：`/lidungeon help`，确认中文帮助正常返回

## 1. 部署与首次启动

### 1.1 服务器文件
- 停机并替换 `LiDungeon-*.jar`
- 启动一次
- 控制台观察日志：
  - 插件是否成功加载；
  - 是否提示配置版本检测/自动补齐；
  - `plugins/LiDungeon/` 是否生成或补齐缺失配置文件；

### 1.2 验证主命令
```text
/lidungeon help
```
- 看到中文帮助且无报错即表示基础入口可用；
- 若命令不可用，先检查：
  - 是否已成功加载插件；
  - 是否有权限拦截；
  - 是否还命中旧入口的执行上下文（可忽略展示，但仍建议统一文案）。

## 2. 第一个副本上线流程（示例：dwdw）

### 2.1 创建副本定义
```text
/lidungeon edit dwdw
```
- 若副本不存在：进入编辑器并可新建副本；
- 若存在：加载现有副本进行校验/编辑；

### 2.2 编辑关键配置（建议顺序）
1. 设置副本出生点与复活点  
2. 设置目标点/出口点  
3. 配置怪物波次（spawn 配置）  
4. 配置触发链（见“触发器与条件”）  
5. 配置奖励池与失败回退行为  

### 2.3 保存与退出
- 编辑完成后执行保存并离开编辑上下文；
- 返回控制台检查是否有保存成功或实例锁定提示；

### 2.4 玩家测试
```text
/lidungeon join dwdw
```
- 确认玩家可进入；
- 确认开始事件与目标事件触发；
- 完成后确认结算逻辑正确返回；

## 3. 多世界实例化建议（生产前）

多世界不是“越多越好”，关键是：
- 预先创建实例世界池；
- 不在高峰时临时热建世界；
- 指定世界池后再对外开放对应地牢；

建议命名风格：`li_dungeon_<dungeonId>_<index>`，便于日志定位。

## 4. 运维建议（第一次上线前必须做）

- 记录一次“编辑时间、保存时间、第一次进入测试时间”；
- 每次改动只改一类参数（例如先只调触发器再调奖励）；
- 发现异常先回到上一版本配置（比回滚 JAR 更快）；
- 对外只写公告 `/lidungeon` 命令与副本说明，避免留给玩家旧入口。

## 5. 常见新手问题

- 找不到副本：确认副本 ID 拼写与 `dungeons` 文件中目录名一致  
- 进入后无事件触发：先检查触发器条件是否完整闭合  
- 奖励未发放：检查奖励动作是否绑定触发器，并确认外部经济/奖励依赖可用  
- 关卡超时：先看副本日志，再确认实例超时参数和清理逻辑
