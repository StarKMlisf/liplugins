# LiDungeon 完整文档

LiDungeon 是一套面向 RPG 生存服与玩法服的中文化地牢系统。它的目标不是“玩一次就能跑”，而是长期稳定地支撑多副本玩法：  
- 设计、编辑、实例化、运行、奖励、回收与运维闭环都可在服务器上持续迭代；
- 兼容原有文档/运维思路，主对外入口改为中文主命令；
- 适配 Paper 26.x 与 Folia 26.2，强调日志可解释、配置可回滚、升级可预期。

## 你需要先知道的两个事实

1. **对外主命令是单入口**：`/lidungeon`  
2. **默认不更改你的既有业务配置值**：仅新增或补齐缺失节点，避免“覆盖式回填”导致定制丢失。

## 能力与边界（先读这个）

### 已明确支持
- 多世界实例化执行（`world pool` 管理模式）
- 地牢编辑（创建、重命名、保存、重载）
- 触发器与条件链路（事件触发 -> 条件判断 -> 动作执行）
- 任务阶段控制（开始、失败、成功、超时/中断）
- 权限分层（管理员/创建者/玩家）
- 日志可观测（启动、编辑、实例分配、重载与触发回显）
- 中文提示（指令帮助、错误提示、状态提示）

### 运行边界
- 配置变更、实例回收、触发器链验证需要在低峰时段执行更稳妥；
- 多世界副本不建议在运行中临时创建新世界，建议预建实例池；
- 外部经济/占位符功能按依赖插件启用，不启用时不应阻塞主玩法；
- Folia 下建议保持世界/区块相关操作在对应调度器上下文内执行。

## 核心模块说明

### 地牢配置层
- 地牢定义文件：定义地图、出生点、终点、怪物池、胜负条件；
- 世界/实例层：处理副本运行时实例（world instance）和玩家绑定；
- 触发器层：把世界事件、时间点、战斗事件转换为动作；
- 命令层：`/lidungeon` 下沉为统一命令树，控制编辑、测试、运维动作。

### 运行时生命周期
1. 管理员初始化/编辑副本  
2. 玩家进入副本实例（分配实例，记录状态）  
3. 副本事件触发（触发器评估 -> 动作执行）  
4. 触发结算与奖励  
5. 完成/超时/异常退出后回收实例、清理状态

## 指令与权限

入口统一后，建议在所有公告、导航和玩家指引中只展示：

- `/lidungeon help`
- `/lidungeon join <dungeonId>`
- `/lidungeon edit <dungeonId>`
- 配置相关重载命令（见当前版本帮助）

更详细的参数与权限在 [命令与权限] 与 [故障排查] 章节后续展开。

## 版本与平台

- 推荐服务端：Paper 26.2（含 Folia）
- 插件兼容目标：Folia 1.21.11
- 推荐 Java：21/25（按你的服务端栈统一）

## 设计取舍（为什么这样写）

- **中文先行**：玩家与服主都用同一套命令词，减少旧入口混淆。  
- **不主动覆盖**：升级只补缺失字段，优先保护已上线的手工定制。  
- **可运维优先**：保留日志与故障排查入口，避免“改了配置看不懂结果”。  
- **多世界友好**：把实例与世界池分开管理，减少单世界阻塞引发的连锁问题。
