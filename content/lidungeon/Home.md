# LiDungeon 完整 Wiki

LiDungeon 是 MythicDungeons 2.0.1 的全中文 Paper/Folia 兼容版。当前发布版本为 `2.0.1-zhcn-folia.8`，对外唯一地牢主指令为 `/lidungeon`，适配 Minecraft 1.21.11 与 26.2。

这套 Wiki 按实际插件源码、默认配置和当前成品 Jar 编写。旧文档中的 `/md`、`/mythicdungeons`、`/md join <地牢>` 等写法不要再用于玩家公告或管理教程。

## 先看结论

- 玩家进入地牢：`/lidungeon play <地牢>`。
- 管理员创建地牢：`/lidungeon create <名称> [类型] [生成器] [维度]`。
- 管理员编辑已有地牢：`/lidungeon edit <地牢>`；`edit` 不会自动创建不存在的地牢。
- `/lidungeon join <玩家>` 是管理员进入指定玩家所在实例，不是玩家进入地牢的命令。
- Paper 可以使用传统动态多世界或单容器世界模式。
- Folia 不能在插件运行期安全创建、加载或卸载世界；正式服应使用已预加载世界池，未配置时回退到单世界远端隔离区。
- 无可选联动时，正常启动会加载 38 个功能、15 个触发器和 9 个条件。安装 MythicMobs、Citizens、PlaceholderAPI 后，对应菜单项会替换或增加。
- 配置升级只补齐缺失节点和注释，不应覆盖管理员已有值；更新前仍必须备份。

## 地牢运行生命周期

一个完整地牢会经历以下阶段：

1. 管理员创建模板，进入编辑实例。
2. 管理员设置大厅出生点、正式出生点、出口、房间、触发器和功能。
3. 玩家或队伍执行 `play`，插件检查权限、人数、距离、等级、费用、钥匙、冷却与可选 JoinSkill。
4. 插件分配可用实例；Folia 会优先分配匹配维度的预加载池世界。
5. 若启用大厅，玩家先进入大厅，等待“开始地牢”功能；否则直接开始。
6. 触发器捕获事件，条件决定是否通过，随后执行一个或多个功能。
7. “完成地牢”功能登记完成记录并按配置开始冷却；“离开地牢”只负责移出玩家，不等同于完成。
8. 最后一名玩家离开后，实例按 `CleanupDelay` 清理并归还池容量。

## 文件与数据

默认数据目录为 `plugins/LiDungeon/`：

| 路径 | 内容 | 备份优先级 |
| --- | --- | --- |
| `config.yml` | 全局队伍、队列、Folia、多世界、旁观设置 | 高 |
| `lang/zh_CN.yml` | 中文消息和编辑器菜单文本 | 高 |
| `maps/default-config.yml` | 新建地牢配置模板 | 中 |
| `maps/default-generator.yml` | 新建程序化地牢生成器模板 | 中 |
| `maps/<地牢>/` | 每个地牢的世界模板、配置、功能和房间数据 | 最高 |
| `globalplayerdata/` | 玩家完成记录、冷却和持久数据 | 最高 |
| `backups/` | 插件生成的历史地牢备份 | 高 |

不要在活动实例运行时直接覆盖 `maps/<地牢>/`。需要替换地图时，先让玩家全部离开，再停服或按[备份、迁移与回滚](备份迁移与回滚.md)处理。

## 支持边界

| 项目 | 当前边界 |
| --- | --- |
| 服务端 | Paper/Folia 1.21.11 与 26.2 |
| Java | 1.21.11 使用 Java 21；26.2 使用 Java 25；插件 Jar 为 Java 21 字节码 |
| 主命令 | 仅 `/lidungeon`；快捷命令 `/leave`、`/ready`、`/notready`、`/recruit`、`/stuck`、`/rewards`、`/party`、`/p` 保留 |
| 地牢类型 | `classic`、`procedural`、`continuous` |
| 程序化布局 | `branching`、`minecrafty` |
| Folia 世界 | 只接管插件加载地牢前已经加载完成、且维度匹配的世界 |
| 可选联动 | MythicMobs、MythicCrucible、PlaceholderAPI、Citizens、Vault、PacketEvents、各类队伍插件等 |

遇到问题时，优先复制完整启动日志、`/lidungeon status` 结果、地牢 ID、服务端构建号和相关配置段，不要只截最后一行错误。
