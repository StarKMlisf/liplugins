# 安装与更新

本页用于服主和运维，目的是让一次插件升级可复现、可回滚、可验证。

## 一、环境要求

### 服务端与 Java
- 服务端：Paper 26.1.2 / 26.2 / Folia 26.2
- Java：按你的主服版本栈一致（建议 21 或 25）
- 兼容目标：优先保证 Folia 调度稳定，插件逻辑在主世界和实例世界一致

### 依赖建议
- Vault（按经济功能）
- PlaceholderAPI（按文本/占位显示需求）

> 说明：缺失依赖不应阻断插件主流程，但涉及对应功能时会在日志中给出可读提示。

## 二、首次安装

### 1. 上线前备份
1. 停机并备份目录：
   - `plugins/LiDungeon/config`
   - `plugins/LiDungeon/dungeons`
   - `plugins/LiDungeon/data`
2. 记录当前运行中的副本 ID 列表和世界池配置。

### 2. 替换文件
1. 替换 `LiDungeon-*.jar`
2. 重启一次服务端

### 3. 首次加载核验
- 控制台出现加载成功与配置初始化日志；
- 插件版本/兼容信息可读；
- `config` 下缺失项已自动补齐；
- 旧入口提示（如保留兼容时）与新主入口 `/lidungeon` 共存可见。

## 三、更新流程（推荐）

### 小步更新（建议）
1. 在测试服先跑一次启动；
2. 执行基础命令验证：`/lidungeon help`；
3. 选一份已知副本执行编辑/进入/退出路径；
4. 观察日志无误后再推生产。

### 全量更新（必须）
- 配置结构变化较大时，先在离线环境完整验证；
- 检查 `dungeons` 下关键副本配置是否有关键字段缺失；
- 进入生产服前执行一轮副本回归测试。

### 回滚策略
- 仅回滚配置不总是足够：建议保留上一版 JAR；
- 遇到运行异常先回滚上一个稳定构建，再分步复现差异；
- 记录每次启动日志片段，作为后续对比依据。

## 四、配置迁移规则（保守模型）

- 不强行覆盖管理员已有值；
- 补齐缺失节点优先；
- 兼容性关键字段保留旧值；
- 运行前对关键字段先做人工核对（尤其是触发链、世界池、奖励动作）。

> 核心原则：**稳定 > 快速，先可跑再扩展**。

## 五、版本发布后核验清单（每次都做）

- 插件入口：`/lidungeon help` 可见；
- 副本列表/目标副本可进入；
- 至少一条触发链能完整执行；
- 奖励结算有回显；
- 实例退出后状态可回收；
- 服务器日志无持续阻塞、无明显超时等待堆积。
