# 自动称号与进阶

自动称号把玩家统计、击杀、原版进度、自定义成就、Vault 余额和上交物品组合成长期目标。玩家使用 `/lititle stats` 查看进度，使用 `/lititle advance` 查看进阶链。

## 支持的目标

### 统计与指定方块

```yaml
statistics:
  - statistic: "MINE_BLOCK"
    display: "砍伐原木"
    materials:
      - "OAK_LOG"
      - "SPRUCE_LOG"
    minimum: 100
```

`materials` 留空或写 `*` 表示所有可用方块。

### 击杀目标

```yaml
kills:
  - entities:
      - "ZOMBIE"
      - "SKELETON"
    minimum: 50
```

`entities` 留空或写 `*` 表示所有可用生物。

### 进度与自定义成就

```yaml
advancements:
  - "minecraft:story/mine_stone"
achievements:
  - "first_join"
```

自定义成就可由管理员或其他系统执行：

```text
/lititle ach complete <玩家> first_join
```

### Vault 余额与上交物品

```yaml
vault-balance: 1000
submit-items:
  - material: "DIAMOND"
    amount: 3
  - material: "EMERALD"
    amount: 10
```

余额目标只检查余额，不扣金币。配置了 `submit-items` 后，玩家必须主动输入 `/lititle submit <称号ID>`；插件确认所有条件后才扣除物品并解锁。

## 多目标与进阶

同一称号可以同时配置多种条件，所有条件均满足后才能获得。`advance-from` 用于声明前置称号，适合把“新手 → 熟练 → 大师”做成进阶链。

统计 GUI 支持以下变量：

```text
%progress%
%progress_bar%
%requirement_lines%
%desc%
```

其中 `%desc%` 展开称号自己的 `lore`。管理员可在 `gui/statistic_title_gui.yml` 调整进度条字符、状态文字、条件模板与 Lore 排列。

## 管理建议

每个目标都应给出清楚的 `display` 与 Lore，避免只让玩家看到内部枚举名。上线前用测试账号验证统计增量、提交物品、前置称号和重新登录后的持久化。
