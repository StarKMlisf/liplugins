# 常见问题

## 玩家聊天没有称号

检查玩家是否已经佩戴称号、聊天模块是否启用、频道格式是否包含 `%title%`，然后执行 `/lititle reload`。推荐把 `%title%` 放在玩家名之前。

## 称号显示在名字后面

调整聊天格式变量顺序：

```yaml
format: "&7%title%&f%lititle_chat_name%&8: &f%message%"
```

## 给了权限仍打不开菜单

确认权限节点与功能一致。基础菜单是 `lititle.use`，聊天颜色是 `lititle.chat.color`，中文昵称是 `lititle.nickname.self`，英文彩色昵称是 `lititle.nickname.color`。`lititle.rename.self` 控制自定义称号，不控制昵称。

## 英文彩色昵称不能输入中文

这是预期规则。`/lititle colornick` 只接受英文字母、数字、下划线与颜色代码；中文昵称请使用 `/lititle nickname`。

## TAB 应该使用哪个变量

推荐 `%lititle_chat_name%`。它会按“彩色英文昵称 → 中文昵称 → 原名”选择显示内容。只显示称号时使用 `%lititle_title%`。

## 跨服后称号或昵称不同步

检查所有子服是否连接同一个 MySQL、数据库账户是否有读写权限、数据是否已从 SQLite 迁移，以及本地称号 YAML 是否一致。MySQL 不同步本地配置文件。

## 跨服聊天收不到

玩家资料同步正常不代表聊天链路正常。检查 Redis 或代理通信、每个子服的聊天模块、频道权限、收听权限与 `server-name`。

## 上交物品后没有自动解锁

带 `submit-items` 的称号不会自动扣物品。玩家需要在满足其他条件后执行 `/lititle submit <称号ID>`，并确保物品类型与数量完全匹配。

## 已拥有称号时使用卷轴

卷轴不会被消耗，这是防止重复领取造成损失的正常保护。

## 更新后没有看到新配置

插件不会整份覆盖已有配置。先备份旧文件，再对照新默认配置合并缺失节点；需要重新生成时只删除目标文件，不要删除整个数据目录。

## 什么时候必须重启

修改普通文本、称号、商店或卷轴通常可重载。切换数据库类型、连接信息、运行依赖或跨服架构时应完整重启。
